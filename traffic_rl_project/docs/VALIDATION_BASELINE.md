## 验证原则

1. **公式层**：代码实现的动力学公式应与论文公式一致（Davis 阻力、牵引、制动、车钩力）。
2. **数据层**：论文提供的定量结果（如某工况下车钩力峰值）应作为回归测试的期望值。
3. **规律层**：论文揭示的物理规律（如制动管减压越大→压钩力越大）应作为行为测试断言。
4. **算法层**：论文的算法/奖励设计与你的 MAPPO 迁移对照，验证方法合理性。

### V3.5.1 长大下坡变坡剖面实现（2026-08-12，P1.5 第12条）

**实现**：
- 新增 `src/train_dynamics/grade_profile.py`：`GradeProfile`（分段坡度剖面）+ 3 种预置剖面（樊运新）：
  - `profile_long_downhill()`：长大下坡（-2‰→-10.2‰→-2‰）
  - `profile_gradual_to_steep()`：缓坡变陡坡（-3.6‰→-9.5‰，坡度差 5.9‰）
  - `profile_v_shape()`：V型坡（-12‰→-1.5‰→-12‰，坡度差 10.5‰）
- `TrainDynamics.set_grade_profile(profile)` + 每步 `_update_grade_from_profile()` 按车辆位置实时更新坡度
- `TrainFormationEnv` 配置 `grade_profile: 'long_downhill'/'gradual_to_steep'/'v_shape'`

**验证结果**：
- ✅ 9 个测试通过（`tests/test_grade_profile.py`）：段边界查询、批量查询、3 种剖面存在、V型坡差≥10‰、列车运行时坡度实时更新、长大下坡加速、环境集成
- ❌ **失败测试留痕**：`test_downhill_accelerates_train` 初版失败——列车从 -2‰ 缓坡段起步（500m 内），-2‰ 坡度助力（~0.02m/s²）小于 Davis 阻力，列车减速而非加速。**期望**：长大下坡加速；**实际**：v0=15→v1=14.89。**原因**：列车未进入 -10.2‰ 陡坡段。**修正**：把列车放到 -10.2‰ 段（位置+600m）后验证加速通过
- 📌 **教训**：长大下坡的"加速"效应依赖坡度大小——缓坡（-2‰）助力不足以克服阻力，需陡坡（-10.2‰）才会净加速；这也解释了为什么长大下坡需要**循环制动**调速（防止超速）

### V3.5.3 Zhang2024 验证基准提取（2026-08-12，P1.5 第14条）

**来源**：Zhang, Zhou, He 等. *Deep Q-Network Algorithm-Based Cyclic Air Braking Strategy for Heavy-Haul Trains.* Algorithms, 2024.

**RL 设计（直接对标，可复现/对照）**：
- **状态**：列车速度 + 时间（s_k = [v, t]）
- **动作**：电制动设置 + 空气制动档位（"setting of electric braking and air braking notch"）
- **奖励/目标**：
  - 安全：速度保持 V_min ≤ V ≤ V̄（长大下坡限速上下界）
  - 空气制动距离 L_a（维护成本，越小越好）
- **约束**：
  - 速度限制：V_min ≤ V ≤ V̄
  - 空气充风时间：制动循环间隔 ≥ T_a（最小充风时间，保证下次制动有足够风压）
- **算法**：DQN + 神经网络逼近动作价值 + 优先经验回放（按重要性/奖励采样）
- **验证数据**：朔黄线（Shuozhou-Huanghua）实测轨道数据，DQN vs Q-learning
- **效果**：**空气制动距离 -2.1%，平均速度 +7%**
- ⭐ **关键差异**：**明确忽略车钩力**（"interaction forces between the cars are not taken into account"）

**对你的验证价值**：MAPPO（考虑车钩力）效果应对比 Zhang2024 DQN（忽略车钩力）——制动距离、平均速度、**车钩力峰值**（Zhang2024 无此指标，是你的增量贡献）；环境已支持（`grade_profile: 'long_downhill'` + 万吨级编组）；奖励可参考其"安全 + 空气制动距离"约束设计。

### V3.5.3b 编队/列车群组 RL 奖励设计文献基准（2026-09-09，多列编队 reward 重构依据）

**背景**：formation-aware 机车级 ED/AB（3列×1+1=6 agents）训练发散（ep20 前 −11万~−12万，进 5000 步段 violations 暴增 213~247、peakCoupler 涨破 1000kN）。复盘发现：上一版把 `_calculate_reward_decomposed` 的 speed_band 从"逐列 ±5/-20"改成"群组均速带二值门槛 +5×3/-20"——3 列异步动力学下几乎不可能同时进带，探索期长期只有惩罚、无正 shaping，策略学不出来。据此从文献库提取多列/列车 RL 奖励设计的权威范式作为重构依据（出处见各条）。

**① Zhang2021 MADRL 列车编队（多列协同，最贴近本项目）**：`docs/papers/03_formation/Zhang2021_MADRL_TrainPlatoon.txt`（Zhang, Zhao et al., IEEE Access 2021）
- 逐 agent 奖励：`r_n = f(e_{n-1,n}, v_{n-1,n})`，由**距离势场 r_e** 与**速度差势场 r_v** 叠加
- 连续 APF（artificial potential field）编码，非二值：**越靠近目标奖励越大**（零势点最大）
- **负项优先、正项隐藏**：只要距离/速度任一项为负（偏离目标），正项被隐藏，输出负；双项皆正才叠加
- 参数：固定奖励 R=400，距离边界 D=10m，动作 3 档 {a⁺,0,a⁻}
- 编队定义：**leader-follower**，follower 只对相邻前车 `e_{n-1,n}` + `v_{n-1,n}` 负责（无需全列齐步）
- 通信：单向→双向，虚拟 leader 调控规定运行线与路线

**② Guo2025 LSTM-MAPPO 车队（同 MAPPO 算法）**：`docs/papers/03_formation/Guo2025_MARL_PlatoonConsensus.txt`（Guo et al., Computer-Aided Civil & Infrastructure Engineering 2025）
- 双向协同优化机制，LSTM 捕捉车队长时动态
- 目标函数显式 minimize 共识误差：间距误差 `eᵈ_{i,i-1}(t)` + 相对速度 `eᵛ_{i,i-1}(t)` + 加速度差 `eᵃ_{i,i-1}(t)`
- 代价 = leader 与前 `eᵈ_{i,0}`/`eᵛ_{i,0}` trade-off + follower 舒适度
- **舒适度项**：`R_c = jerk·(a(t)−a(t−1))/Δt`（jerk = 加速度变化率）
- **大负值惩罚 −15**：速度低于目标时触发的强惩罚，促使 agent 决策正确方向
- 效果：平均间距误差 −8.3%、编队平均长度 −19.1%（vs 共识控制）

**③ Zhang2024 DQN 循环制动（长大下坡逼近工况）**：`docs/papers/02_rl/Zhang2024_DQN_CyclicBraking_Downhill.txt`（见 V3.5.3）
- 长大下坡唯一减速手段 = 循环空气制动（与本项目一致）
- 奖励直接在**车辆运行约束**（限速 V_min ≤ V ≤ V̄）+ **性能指标**（制动距离）上构建，DQN 可收敛
- 单列、**忽略车钩力**——本项目在此基础上的增量 = 建模车钩力 + 扩展到多列编队

**三篇共性结论（→ `_calculate_reward_decomposed` 重构原则）**：
1. **逐 agent 势场**：每 agent 只对自身相对前车的距离误差 + 速度差负责，用连续 APF（非二值门槛）
2. **负优先但"可达"**：负项只在真偏离目标时出现；奖励标到让 agent 能学出正向行为，避免探索期长期负酱
3. **不要求全列齐步**：leader-follower 相对信息，异步动力学仍可学
4. **大负值惩罚用于硬约束**（碰撞/超限），与连续势场正项分开设计
5. **多目标显式化**：间距误差、速度差、（可选）jerk 各自成项，按任务权重叠加

> 留痕结论（失败不删，作修正依据）：2026-09-09 上一版"群组均速带二值门槛" designs 违反原则 1/2/3，是发散根因；重构按上表原则执行。原始发散 history 见 `outputs/checkpoints/formation/seed0/results/train_history_dec_ad2_cp_seed0.json`（ep1-30: rewards 反复 −4万~−45万，violations 0→247，peakCoupler 800→1376kN）。

### V3.5.4 Zhao2022 空气制动精细建模验证基准（2026-09-02，文献初始化）

**模型要点（三段式空气制动）**：响应（手柄→头车充气）+ 暂态（头车→尾车充气结束）+ 稳态；闸瓦压力分布 K_{z,i}(t)（λ_z 阀特性/γ_z 波速特性/K_z 充气特性）× 历史操纵修正 P_s(t)（λ_s/k_s 闸瓦温度/K_s 缓解时间/C_β 减压量修正）。

## 四、ETCS 目标距离超速防护曲线（"真 ATP"）验证基准

> **来源**：《Introduction to ETCS Braking Curves》，欧洲铁路局 / ERTMS（ERA_ERTMS_040026 Version 1.5, 2020），`docs/papers/04_safety_mpc/ERA_2020_Introduction_to_ETCS_Braking_Curves.pdf`。本节全部公式与数值均引自该文档（§3 模型、§5 数值示例）。对应 `docs/logs/progress/PROGRESS_2026-09.md` 立项任务「实现真正的 ATP」，回答答辩质疑"你的 ATP 是假的"。
> **诚实边界**：本复现聚焦**车载超速/限速防护曲线（速度监督）**，非闭塞/信号层的进场授权（Movement Authority）。"防追尾属信号级 ATP 职权，我们补充车钩力+缩短安全间隔"的叙事据此成立。

### 4.1 目的：把"假 ATP"升级为"真 ATP"

现状 [safety_layer.py](file:///d:/Code/MultiAgent/traffic_rl_project/src/safety_layer.py) 规则1 是**反应式软修正**——`vel >= 限速` 就把动作钳到 `-0.75`（full service），缺前方目标距离/坡度分量/制动建立延迟/前瞻监督层级。

ETCS 目标距离超速防护曲线是**前瞻式抛物线监督限位**：对每个前方目标点（降速点 / EOA 停车 / 间距约束点），从目标反推「紧急制动减速曲线」（EBD），再叠加最不利假设得到介入点（EBI），按五级监督驱动制动——只要在 EBI 触发紧急制动，就保证不越过目标点。

### 4.2 核心公式（PDF §3）

**EBD（紧急制动减速曲线，§3.3.1）**：抛物线集，从目标位置反推，总保证减速度为

```
A_safe(v, d) = A_brake_safe(v) + A_gradient(d)
A_brake_safe(v)  保证紧急制动减速度（对速度的分段常值 step function，"emergency brake deceleration profile"）
A_gradient(d)    坡度加速度分量（对距离的分段常值，"gradient profile"；下坡为正加速 A_gradient>0）
```

- 二者分段组合 → 一组互相衔接的抛物线弧（图 4）。**坡度分量对长大下坡 = 减速度被坡度"吃掉"，曲线变平、制动距离变长**——正好对应本项目场景。

**保证紧急制动减速度（§3.3.2）**：名义减速度经滚动/线路校正因子折减，得"保证"值（Kdry 对应干轨 10⁻⁹ 置信水平）：

```
A_brake_dry    = A_brake_emergency × Kdry_rst        # 干轨保证减速度
A_brake_guaranteed = (1-加权) × A_brake_dry + 加权 × A_brake_dry × Kwet_rst   # 湿轨加权（Kwet<1）
Kdry_rst        滚动校正因子（干轨性能离散度，Monte-Carlo 离线求，置信水平→10⁻⁹）
Kwet_rst        湿轨粘着损失校正（EN15595，案例 0.893）
```

**EBI（介入限位，§3.1.1）** = EBD 基础上叠加**最不利假设**：
- 制动建立时间 `t_build_up`（紧急制动全制动力建立前）内按**实测/假设加速度**继续加速；
- 叠加**速度测量误差** `v_err`（SUBSET-041 性能要求，案例 2.58%~3.49%）。

即 EBI 位置 = 对当前速度，按 `EBD(v + v_err)` 对应的制动距离 + 建立时间内以 `A_assumed` 走过的距离，二者返回到路面的点。工程实现：从 EBD 曲线向"更早介入"方向平移/抬升。

**五级监督（§3.1.2 与图 1）**：

```
I（提示，留给司机反应） → P（许可速度，超限预警） → W（附加声音警告）
→ SBI（服务制动介入，可选，留服务制动建立时间的余量） → EBI（紧急制动介入，硬触发）
```

级间用**司机反应时间**隔开（ETCS 固定值）：`driver_time(I→P)`、`driver_time(P→EBI)` 等。ETCS 实时**只算当前速度对应的单个限位**，非一次性整条曲线。

**制动建立时间对本项目的对齐**：紧急制动全车制动力建立需等待空气制动波沿车列传播（见 `braking.py` 波速传播），本项目用**车辆累计长度/波速**计算该延迟（不是车钩 free_length，否则会被 dt 吞掉）——这一延迟即 `t_build_up` 的物理来源，直接与 ETCS 的"制动建立时间"对齐。

### 诊断-2026-09-02-MARL优势相对MPC四局限 + 标准MARL难题两问（导师答辩准备）

**背景**：导师提出两条必须回答的问题——①重载列车控制特征/难点、为什么标准 MARL 解决不了；②对标准方法做了什么改进、为什么能解决。同时要求对照 MPC 四大局限说明 MARL 在哪些方面更好。本小节记录分析结论（**试验阶段，非论文叙述**），作为答辩/试验论证素材。

#### A. 重载列车控制难点（四个本质难点）

| # | 难点 | 说明 |
|:--|:--|:--|
| 1 | 多物理尺度时间常数并存 | 快：101 质点刚性动力学，空气制动按波速 200m/s 沿 1km+ 车列传播，秒级制动建立 + 纵向冲动（车钩力），0.1s 积分需内部 ≤0.01s 物理子步否则发散；慢：长大下坡循环制动是**分钟级相位**（缓坡蓄速→陡坡提前制动→缓解），一循环跨数十秒~数分钟 |
| 2 | 高维 + 非线性强耦合 | 多列 × 每列 101 质点 × 多特征；车钩力由质量-弹簧-阻尼 + 间隙死区 + MT-2 迟滞（预压力+摩擦+弹力）产生，非线性和成对（牛顿第三定律抵消），全系统强耦合 |
| 3 | 硬安全约束（非软目标） | 车钩力≤1000kN、列间距≥下限、线路限速、低速 40km/h 以下不得缓解；且部分动作是离散档位 + 传播延迟，非 RL 假设的连续平滑动作 |
| 4 | 稀疏 + 延迟 + 长因果回报 | 长评估 3000 步 / 20km+，"提前蓄速/提前制动"因果跨数十秒兑现，奖励在分钟级制动事件才显著 |

#### B. 为什么标准 MARL 解决不了（映射实测）

1. **信用分配失效**：缓解波长时延 ~6s + 分钟级相位，PPO/MAPPO 折扣窗口捕捉不到跨分钟因果 → 只会跟瞬时速度抖动。实测**直接学单列循环制动结构性失败**（`hierarchical_controller.py` L10 记载，连续/离散/warm start/循环引导全失败）。
2. **探索即爆炸**：车钩力多体强耦合，早期随机探索即触发车钩力/间距越界 → violation 爆炸 → SafetyLayer 修正动作后 log_prob 未重算 → 重要性采样失效 → 策略发散（V5.1 三层 bug 链：viol 每 10ep 爆 85 倍）。
3. **安全只做成奖励惩罚不可落地**：收敛后无解析安全保证，无法作为行车控制器。
4. **样本效率极低**：101 质点 × 多列 × 长步数，平面策略要同时学快物理+慢决策+安全，学太多 → 收敛慢/不收敛。
5. **浪费强先验**：标准 MARL 把每列当独立同分布个体，忽视"所有列车共享同一物理规律"这一强先验。

#### C. 对标准方法的改进与为什么能解决

1. **分层解耦（核心）**：微观层（层级二）用**规则循环制动** `get_action_cyclic_braking` 控速（领域最优，固化运行经验 + 波速物理 + 车钩力安全钳制，不用 RL）；宏观层（层级一）MARL 每列输出协同阈值偏移 `coor_adj`（限 ±5km/h），只调循环制动触发/缓解阈值、不直接动 throttle。→ 把快物理+硬安全+经验抽离 RL 探索空间，RL 只学慢时标 1 维宏观协同 → 稳定可学。实测 M1 vs M3 协同增量 **+26k（gap100）/ +47k（gap40）**。
2. **ATP/ETCS 前瞻安全包络**：把防追尾/超速从 RL 奖励/约束抽离，交给 ETCS EBD/EBI 五级监督兜底（反应式限速兜底线速）。→ RL 无需在线保证安全，聚焦约束下控制质量；同时让 MARL vs MPC 公平（追尾都由 ATP 兜底）。
3. **问题表征重塑**：状态聚合（速度误差/间距误差/车钩力统计/前方坡度，非 101 质点全状态）；动作连续直接控目标加速度/阈值偏移 → 降维、有真实区分度、样本效率↑。
4. **奖励塑形**：单标量 = −0.5速度误差 −0.3间距误差 −0.15平均冲动 −0.15峰值冲动 + 超限惩罚，把车钩力（冲动）与舒适性显式量化进目标。

**诚实前提（须在答辩/论文主动声明）**：分层本身是强先验/领域结构，第1层规则承担大量任务，**协同增量来自结构分工而非纯端到端学到的协同**；MARL 代价仍在（训练开销、可解释性弱、安全依赖 ATP 兜底而非解析保证）——作为 Limitations。

#### D. MARL 相对 MPC 四大局限的优势映射（实测证据）

| 导师给 MPC 的局限 | MPC 的痛 | MARL 好在这 |
|:--|:--|:--|
| ① 终端无解/终端约束难设计 | 每步在线求解带不等式约束（间距≥gap_min、车钩力≤1000kN、限速）的非凸优化，多约束挤压时 SLSQP 在 maxiter 内无解→崩溃 | 无"在线求可行解"概念；约束靠策略习得纪律 + ATP/SafetyLayer 兜底。实测 M1 追尾 0、车钩力峰 659kN；M-MPC 崩盘（−115k、低40 71.6%、车钩力 1178kN 超限） |
| ② 无法应用司机经验 | 目标函数必须写成解析二次代价；司机"缓坡蓄速→陡坡制动"是跨分钟节奏，滚动时域（秒级）看不到，只能手工调 λ | 奖励可编码运行规制；分层第1层规则循环制动即固化司机经验，第2层学剩余协同。实测 M-MPC 仅 4.2 次循环制动、速度崩下限之下；M1 稳定巡航 |
| ③ 需要极其精确动力学模型 | 预测依赖 Davis 阻力/车钩力模型/列间耦合；101 质点 Newmark 在优化器内跑不动→聚合列模型（模型误差累积→长时域漂移），车钩力只能用相对速度代理 | 模型无关，TD 天然容错随机转移，对 Davis/车钩力建模误差鲁棒 |
| ④ 泛化弱 | gap_min/λ/时域 B 针对线路标定，换线路/列车要重新调参建模 | 分层规则层承担线路无关部分（long_downhill→20km 免调参可用）；第2层统一框架快速适应。M1 跨线 +36,120 复现主剖面结论 |

#### E. 30-40km 长下坡验证剖面（学长建议，2026-09-02）

**背景**：学长建议验证 30-40km 长大下坡；发现当前评估实为**浅覆盖**——`MAX_STEPS=3000`、`dt=0.1` → 300 仿真秒 → 巡航约 5km，仅采到朔黄 23.8km **前段变坡区**，并未跑完整剖面。

**决策（用户确认）**：
1. **新增 `long_downhill_35km` 剖面**（`grade_profile.py`）：全新设计、**明确标注 synthetic**（不冒充真实纵断面），≈35km，连续 -9.5‰~-11.5‰ 多段变坡（坡度差 ≤10.5‰，樊运新约束），长鼻段制造持续追尾压力，作第三线路/外推/压力验证。冒烟：max_start=34500，grade_at 1000/5000/12000/24000/33000/35000 = −2‰/−9.5‰/−11‰/−11.5‰/−7‰/−2‰ 正确。
2. **`MAX_STEPS` 对齐 35000**（`evaluate_m1_m3_long.py`）：35km 巡航约 2100s=21000 步、v_min 兜底约 31950 步，默认 35000，`--max_steps` 仍可覆盖。

**重训判断（分层）**：第1层规则循环制动**免重训**（确定性、线路无关，已验证 20km 跨线免调参）；第2层 MARL 协同**需重训**（obs 含前方坡度，有分布偏移；历史对 20km 即完整重训）。两类用途分清——公平/论文对比→35km 上重训 Layer-2；跨线鲁棒性外推→朔黄模型直接扔 35km eval（先抽 1 模型冒烟）。episodes 的 max_steps 同步需拉长（否则训练同样只采前段）。

**公平性修正（2026-09-02）**：基线 M-MPC 原用**恒定坡度**（前 5 车均值）做预测，实为不公平弱化（现实中 MPC 掌握完整线路图纸）。已改 `fair_mpc_controller.py`：注入 `grade_at` + `pos0` 位置演化，沿预测位置**前瞻真实坡度**。冒烟验证 pos 1000/2000/3000 返回 −7.5‰/−10.9‰/−10.9‰ 与朔黄线剖面吻合。此举把 M-MPC 局限归结到**结构性**（短时域 + 依赖精确模型 + 在线求解）而非模型简化；下一步在 `enable_etcs`（--etcs）兜底下重跑 `mpc_dir` 验证 M-MPC 止血与 M-MARL 增益是否保留（待手动执行）。

### 诊断-2026-09-02-ETCS性能173x优化 + 间距目标速度修复（35km追尾根因）

**任务**：跑 35km + `--etcs` 评估时发现单 seed 评估异常缓慢，且首跑结果暴露"真 ATP 不追尾"承诺在 35km 合成剖面上失效。

**① 性能优化（ETCS 热路径，173x）**：
- **现象**：`supervision_levels` 均值 **383 ms/次** → 35000 步×3 列仅 ETCS 约 **11 小时**，35km 评估完全不可行。
- **根因**：安全层只需 EBI/SBI 两级，但 `supervision_levels` 计算五级（I/P/W/SBI/EBI）共 **5 次二分 × 60 次迭代 × 每次 `braking_distance` 前向积分 O(数千)**（全纯 Python，dv=0.05）。
- **解决**：`etcs_braking.py` 新增 `supervise_targets()`——对每个目标**一次前向积分构建 v↔制动距离单调表**，EBI/SBI 各一次 `np.searchsorted` 查表；`safety_layer._etcs_check` 改走该路径。公共 `supervision_levels`/`v_allowed` 语义不变（测试不受影响）。实测 **2.2 ms/次**（**173x**），35000×3 步 ETCS 由 ~11h 降到 ~4 分钟。
- **复现命令**（临时脚本已删）：`python -c` 构造朔黄剖面 + 目标 5000m@16.7m/s 计时。

**② 间距目标速度修复（35km 追尾根因）**：
- **首跑结果（修复前）**：M1 模型（朔黄/20km 训练）直接外推到 35km + ETCS（`--grade long_downhill_35km --etcs --n_seed 1`）：
  reward **−8,163,926**｜超80 **1.3%**｜低40 **2.1%**｜车钩力峰 **815kN**（未超 1000，正常）｜**间距min −5401m、追尾步数 28581/35000**｜循环制动 24 次。
- **根因**：`train_fleet_env.py` 给后列注入的 ETCS 间距目标 `EbdTarget(speed_mps=self.target_speed)`——用**固定巡航参考 16.7m/s**，而非**前列当前实时速度**。35km 合成长坡前列频繁循环制动降速（≤40km/h=11m/s）时，后列仍被允许按 16.7m/s 逼近前列尾 → EBD 预留距离不足以应对"前列更慢" → 后列穿透前列（28581 步 gap<5m、min=−5401m）。"真 ATP 保证不追尾"在长坡循环制动场景失效。
- **解决**：目标速度改为**前列当前实时速度** `self.trains[i-1].dynamics.vel[0]`（后列须在到达前列尾前降到前列当前速度）。语义与 VCTS 移动目标监督一致。新增测试断言目标速度=前列当前速度，全套 **111 passed**。
- **物理说明**：静态 EOA 点目标用目标点固定速度即可；**间距约束型（kind='gap'）目标追踪移动体，目标速度必须跟随被追踪体实时速度**，否则监督失去"防后车追上前车"的物理含义。这是车载 ATP 距离监督在**虚拟耦合移动目标**场景下的必要修正（与王国／动态安全间距文献一致）。

**待续**：修复后重跑 M1 35km+ETCS 验证（结果记录见 `docs/logs/diagnostics/`）。

### 诊断-2026-09-06-敏感性扫描：μs/μd 与 v_er 对循环制动车钩力峰值的独立归因

**触发**：审稿人第二箭——"μs/μd、v_er 是否主导朔黄循环制动车钩力峰值结果"。对 **MT-2 摩擦两个标定参数**做单参数独立归因，复用 fig3 协议（`10kt_1plus0` + `shuozhou_23800` + 15000 步 + `TrainLowLevelController` 规则循环制动 80↔40km/h + `enable_safety=True`）。

- **v_er 不敏感**：全范围 0.05→0.5 峰值仅 +1.0%，单调温和上升。原因：运行时缓冲器相对速度/缓解冲击处于 v_er 附近过渡区，0.05→0.5 只是把"静摩擦窗口"拉宽，摩擦在静/动间略切换，对峰值影响 <2% → **该参数对主结果不起主导作用，审稿低风险**。

**结论（对审稿人的诚实边界）**：
- 两个标定参数在所选标定值处的 ±合理不确定度内对主场景车钩力峰值影响 **≤~1%** → **均不主导头号结论**（循环制动车钩力），审稿"参数主导结果"质疑可被数据驳回。
- 需在 Limitations/诚实边界补充一句：μs/μd 峰值单调递增，且在 ~1.8 存在阈值非线性（峰值 +15.8% + 末速跳变），本项目取 1.5（平缓段）为保守合理值，未触及阈值。这是扫描获得的**新边界知识**，比"文献单点标定"更严格。

### 诊断-2026-09-09-53km 追尾真根因：ETCS 紧急制动未传导为空气制动（安全层修复）【物理：MT-2 统一 + Newmark-β + 两段式缓解；剖面 shuozhou_real_53km】

**触发**：「诊断-2026-09-09-53km 双线发散」判规则层在 53km 负间距追尾，用户质疑"ATP 已完善不会追尾，是调用错或 ATP 被破坏"。据此定位到**安全层调用路径**，实证推翻"规则层缺陷"假设、锁定真正根因。

**根因（三层层递进）**
1. **表象层**：53km 规则裸跑（`enable_etcs=[True,True,True]`）仍 `RULE_TRACE_DIVERGES`，final_gaps=[-580.9,-144.1]。
2. **ETCS 触发实证**：在 trace 中统计 safety_events，结果 **`etcs_ebi=3643 / etcs_permitted=286`（6000 步内）**——ETCS 饱和触发紧急制动，但列车照样穿透前列（gaps→-776）。**ATP 逻辑在跑、报 EBI，却拦不住**。
3. **翻译层根因**：[train_env.py `_step_decomposed`](src/environments/train_env.py) 中安全层 EBI 的"紧急制动"**只被翻译成机车 ED 加深**（`proj_throttle`→L498-500 压 `ed_throttle`），而 `ab_command` 恒 RELEASE（L482）、`ab_sources` 由 RL 动作决定。→ 长大下坡上 2 台机车的电制动**刹不住 100 节万吨列车**（电制动无全列传播、功率受粘着约束），ETCS 拼命报 EBI 但列车仍溜坡穿透。**这就是"ATP 被破坏"的本质：不是没调，而是紧急制动没真正传导到空气制动。**

**修复（`src/environments/train_env.py` L497-505 + `src/train_dynamics/etcs_braking.py` L377-394）**
- **主修复（真制动）**：`safety.protect` 后，若 `last_events` 含 `etcs_ebi`，把 `ab_command` 提升为 `AirBrakeNotch.EMERGENCY` → ETCS EBI 真正施加**全列空气紧急制动**（沿波速传播），才能对抗下坡重力拖住列车。
- **配套（越过后豁免）**：`supervise_targets` 原 `if position_m >= target.position_m: continue` 越过前列尾即豁免 ×。改为越过后（avail≤0）允许速度压到 `target.speed` 下方，避免越过瞬间零约束。

**实证结果（53km 纯规则 trace，`tmp_53km_rule_trace.py` 加 ETCS 事件统计）**
| 指标 | 修复前 | 修复后（6000 步） | 修复后（完整 15000 步） |
|:--|:--|:--|:--|
| verdict | `DIVERGES` | `RULE_TRACE_OK` | `RULE_TRACE_OK` |

**结论（物理/机制）**
1. **ATP 从未失效，是"紧急制动信号没传导到空气制动"**——之前只加深 ED。用户直觉（ATP 会防追尾）属实；被破坏的是**制动执行链**，不是监督逻辑。

3. **遗留**：vstd=1.745 仍偏高——安全层兜住"不追尾"，但**规则层速度协同仍未锁死**是独立的收敛问题（对应上一诊断的"规则骨架 53km 需升级"），需另修，不属安全层职责。

### 诊断-2026-09-17-多体 NMPC 成熟基线（casadi+IPOPT）两处必踩坑 + 冒烟验证【物理：MT-2 统一 + Newmark-β；剖面 shuozhou_real_53km / long_downhill】

**任务**：按导师口径"不要留粗糙 MPC 当靶子"，用 casadi+IPOPT 实现多体 NMPC 成熟基线（`src/controllers/nmpc_controller.py`，lumped 4 块/列 + MT-2 车钩符号化 + 车钩力≤1000kN 硬约束 + 终端代价 + control blocking），与 D-RL 同档对冲（规则循环制动内层 + NMPC 调制，唯一差异=决策来源）。已接入 `evaluate_decompose.py --mpc_type nmpc`，求解耗时/失败率落评估 JSON。

**坑1（本会话根因）：casadi 1D 参数 + reshape 是列主序填充，与 numpy 行主序 ravel 不匹配**
- 期望：`opti.parameter(n*nL*2)` + `ca.reshape` 承载 `np.concatenate([pos0.ravel(), vel0.ravel()])`。
- 实际：reshape 按**列主序**填充，块位置被打乱 → step1 初始相对伸长 ±1208m → 车钩力预测 5.6e10 N → 速度被 clip 到 2·v_max → IPOPT 不可行。
- 解决：改两个 2D 参数 `opti.parameter(n,nL)`（pos0/vel0 分离），`set_value(2D numpy)` 保持逻辑布局；验证 0 点轨迹全程 max|rel|<0.09m。

**坑2（fleet env 才暴露）：列距符号约定 = 前列尾 − 后列头（head 递减），写成 head 差则符号反置**
- 期望：3 列 fleet（`head` 递减，后列在前列后方，初始列距=200m）首步求解 optimal。
- 实际：IPOPT `Infeasible_Problem_Detected`，首迭代 constraint violation **220**＝符号反置的 −200m 列距（gap 公式写成 `pos[i,0]−pos[i-1,-1]`＝head 差＝−200，违背 `gap≥20m`）。单列求解正常、短冒烟（fake env head 递增）也正常——坑被"单列无列距约束 + fake env 顺序巧合"掩盖，3 列真实 fleet 首步即炸。
- 解决：gap = `pos[k][i-1,-1] − pos[k][i,0]`（前列尾块 − 后列头块）；两端车位置各 +0.5·sp 相抵 → 直接用块中心差。修复后 1/2/3 列首步全 optimal。

**冒烟验证（`tests/test_nmpc_controller.py`，5 项，全部通过）**：
1. 首步求解 `optimal` + 输出契约 `(num_trains,)` 有限且落在 [accel_lo, accel_hi]；
2. 3 列 fleet 首步 optimal（坑2 回归）；
3. NMPC 驱动 40 步 rollout：车钩力峰值 ≤1000kN、viol==0；
4. 与 D-Rule（规则基线零调制）同剖面同时域：车钩力峰值在 2× 带内、ED 深度差 <0.6（同物理带内一致，非粗糙靶子）；
5. solve_times/solve_statuses 逐帧累积、reset() 清空。

**短评估冒烟（60 步，shuozhou_real_53km 起点，3 列×1+1，init 80km/h）**：
- 命令：`python src/evaluation/evaluate_decompose.py --mode mpc --mpc_type nmpc --max_steps 60 --n_seed 1 --enable_mpc --out_suffix _smoke_nmpc`
- 结果：fail **0** / peakCoupler **478kN**（≤1000✓）/ viol 0 / band 100% / meanED 0.992 / MPC求解 **98ms 均值 / 1630ms 峰值**（首步含符号构建）；JSON 含 `mpc_solve_mean_ms / mpc_solve_max_ms / mpc_solve_fail` 落盘 `outputs/results/decompose/eval_decompose_mpc_ms60_smoke_nmpc.json`。
