## 诊断-2026-08-20 E19-E24 长距离多列攻坚 + 下一阶段工作方针确认

### E19-E20 长距离场景：循环制动核心价值体现

**背景**：1500 步场景太短（只跑约 2.7km，未到朔黄线需循环制动的陡坡段），惰行就能跑、循环制动+协同增量小。扩展至完整朔黄线长距离（3000 步）后，核心价值显现。

**完整朔黄线 3000 步惰行 vs 规则循环制动**：

| 方法     | 平均速度     | 最大      | 超80       | 低40   | 循环制动 |
| :----- | :------- | :------ | :-------- | :---- | :--- |
| 惰行     | 83.3km/h | 111km/h | **53.7%** | 0%    | 0次   |
| 规则循环制动 | 48.5km/h | 80      | 0%        | 34.2% | 1次   |

**结论（物理/机制）**：3000 步场景**天然需要循环制动**（惰行超80占53.7%），规则循环制动能控超速但掉速（低40占34.2%）→ 印证 RL 精细控制价值（既控超速又不掉速）。

**RL 第1层长距离（3000步/初始65/warm start/缓解波）评估（随机采样）**：

| seed  | 平均速度 | 最大 | 超80  | 低40   | 车钩力            |
| :---- | :--- | :- | :--- | :---- | :------------- |
| seed0 | 63.4 | 84 | 7.0% | 0%    | 435kN          |
| seed1 | 57.3 | 80 | 0%   | 4.8%  | 702kN          |
| seed2 | 47.3 | 80 | 0%   | 34.9% | 9600kN爆炸(随机噪声) |

**结论**：RL 第1层长距离将超80从惰行 53.7% 降到 0-7%，车钩力守住（多数seed）→ **创新点1（长大下坡 RL + 车钩力）有强证据**（对比 Zhang2024 等忽略车钩力工作）。seed2 爆炸是 RL 随机策略噪声，多次采样取均值规避。

### E21-E24 长距离多列数值稳定攻坚（车钩力 + loss 爆炸两大障碍）

**问题链**：

- E20（3000步多列RL早期）：Reward -30475、车钩力 3335kN 超限 153.9次、loss 112 → 长距离步数多，RL δ 探索破坏列内控速

- E21（δ=0 纯第1层长距离多列）：seed1 追尾（间距-213m穿透、追尾698步，-172万）→ **多列无协同的固有风险，正是协同价值验证场景**

- E22（追尾趋势惩罚 gap\_trend\_penalty）：仍灾难（avg-36074、车钩力3326kN、loss 4.7e12）

- E23（势场clip-200 + returns clip±2e5）：结果与 E20/E22 一字不差 → 非势场/returns 问题

**E24 组合改进（决定性）**：低探索 entropy=0.001 + 低δ adj\_coef=0.1 + 追尾趋势 + 势场clip-200 + returns clip±2e5：

| 指标         | 改进前            | E24                 |
| :--------- | :------------- | :------------------ |
| 车钩力        | 3326kN/超限153.9 | **517kN/超限0** ✅     |
| loss       | 4.7e12 爆炸      | **31.2** ✅          |
| avg reward | -3.6万          | -3.7万（剩掉速/追尾，需训练学习） |

**结论**：车钩力爆炸（低探索解决 δ 破坏控速）+ loss 爆炸（returns clip + 低探索解决）两大障碍已解决。剩掉速/追尾导致 avg 负，需 RL 训练学习协同。

### 决定性认知：协同价值需正确场景（工作记忆 L42-59 回顾）

**核心命题回顾**：群组协同对车钩力贡献=0（此前诊断：车钩力放大 100% 来自扰动制动本身，群组协同贡献 0.0kN）。**该结论成立的前提是"无扰动普通场景"**（如 long\_downhill 连续长坡单次制动）。

**下一阶段正确方向（用户最终确认）**：构造"群组协同主动制造车钩力压力"的场景——**朔黄线真实剖面 + 多列保持间距（虚拟耦合）**：

- 长大下坡**天然需要循环制动**（单列产生车钩力）+ **多列车需保持距离**（虚拟耦合）双重需求天然并存

- 各列循环制动**相位天然错开**，跟随车为保持间距**配合前列的制动/缓解节奏** → 协同价值由场景天然驱动

- **不引入人为扰动**（真实线路本身驱动协同）

**必须验证的增量**：M1（群组协同 + 车钩力） vs M3（单列独立，只循环制动不协同）——证明协同增量（间距/安全）+ 车钩力贯穿约束。

**关联文献出处**：长大下坡需循环空气制动（Lu2025 ICIRT、Si2025 ICIRT、Zhang2024）、虚拟编组 keep headway（Zhang2021 MADRL、Chen2024 VCTS）、车钩力约束（张二田 2021 朔黄线实测 1000kN、Chu2025 铁科院标准）。

### 诊断-2026-08-20 M1 vs M3 长距离对比评估（协同增量决定性验证，诚实负结果）

- **惰行**（throttle=0 baseline）

**决定性结论（诚实记录，不粉饰）**：

1. ✅ **M1 和 M3 都大幅优于惰行**（reward +1.8万\~+3.4万 vs -6.2万，超80从47.2%降到3-7.4%）→ **循环制动控速有效**（创新点1：长大下坡 RL 控制有证据）
2. ❌ **M1（协同）相对 M3（单列独立）无增量，甚至略差**：reward M1(+17692) < M3(+34404)，超80 M1(7.4%) > M3(3.0%)，间距漂移 M1(194m) > M3(170m)
3. ❌ **车钩力 M1(958) ≈ M3(893)** → **协同对车钩力无贡献**（完全印证工作记忆核心命题）

**根因诊断（为什么协同增量=0）**：reset 后各列初始都位于 -1.5‰ 缓坡起点（位置 0 / -283m / -567m，均 <1000m 缓坡区），初始速度同为 65km/h，控速用**同一个第1层策略** → **各列经历完全相同的坡段演化，速度天然同步（全程 std 仅 2.3km/h）**，M3 独立控速已能保持间距（漂移170m不追尾）。M1 的 RL δ 因 E24 训练 avg 为负（best -32508），评估时 δ 扰动反而破坏第1层控速。

**工作方针印证**：当前 reset 布局未实现用户要求的"各列循环制动**相位天然错开**"——各列同起点、同速、同步控速，协同无用武之地。**要让协同体现价值，需让各列在真实编队中天然处于不同位置/坡段**（前列先遇陡坡制动、后列仍在缓坡，相差 \~4km），相位才天然错开。这是场景实现修正（真实编队物理），非人为扰动。

**评估脚本**：`src/evaluation/evaluate_m1_m3_long.py`（保留复现）

**相位错开尝试（补充诊断）**：把各列错开 1800m 到负方向位置（-2083/-4167m），但**朔黄线剖面只定义正方向（0\~23800m），负位置统一返回 -1.5‰**，各列队首坡度仍相同 → 速度 std 仍小（但列0跑到 -10.9‰ 陡坡冲到 86km/h，其余列还在缓坡，列0\~列1间距拉开到 3050m）。**结论**：仅平移位置无法让各列进入不同坡段；要"相位天然错开"需让编队**从中段起步**（各列队首落在正方向不同坡段位置），这是环境 reset 布局修正，非人为扰动。

### 诊断-2026-08-20 E25 方案A 场景实现与评估（中段起步+坡段错开）

**方案 A 落地（用户确认）**：`TrainFleetEnv.reset` 新增 `start_offset_m`（编队中段起步位置）+ `spacing_m`（相邻列队首间距），使各列队首落在正方向不同坡段，循环制动相位天然错开。已验证 reset 正常（列队首 1600/900/200m，坡段错开）。

**方案 A 场景（start\_offset=1600, spacing=700）确定性评估**：

| 间距min     | 600m    | **-228m追尾567步** | 566m        |

**决定性结论（诚实记录）**：

1. ✅ **方案 A 场景制造了更强压力**：惰行超80从普通场景 47.2% 升到 **71.0%**（中段起步后更早进陡坡）；M3 车钩力 1106kN 超限（前列陡坡制动+后列缓坡，缓解不同步放大车钩力）——协同/优化有更大改善空间
2. ❌ **现有 E24 模型（普通场景训练）在方案 A 场景泛化差**：M1 间距追尾 -228m/567步、reward -161686。根因：E24 在"各列同坡段"场景训练，obs 分布与方案 A（坡段错开）完全不同 → 泛化失败 → **必须在此场景重训 M1**
3. ⚠️ **方案 A 场景训练难度大**：30ep 冒烟 reward -15万（vs 普通场景 E24 best -32508）。start\_offset=1600 让各列快速进陡坡，speed\_band 惩罚重 + 坡段错开致间距/速度惩罚累积

**关键权衡（待解决）**：方案 A 场景"坡段错开需大间距" vs "协同价值需近间距"存在根本矛盾——spacing 大则各列初始间距大、追尾风险低、协同价值小；spacing 小则各列坡段难错开。需仔细设计 start\_offset/spacing 使各列速度产生真实持续差异、间距自然缩小到协同必要的区间。**这是方案 A 的核心设计难点，不能盲目训练。**

**代码**：`train_fleet_env.py`（reset 支持 start\_offset/spacing）、`train_fleet.py`（--start\_offset\_m/--spacing\_m）、`evaluate_m1_m3_long.py`（支持场景参数）、`tmp_verify_env_skew.py`/`tmp_compare_m1m3_skew.py`/`tmp_smoke_env.py`（诊断，临时）

### 诊断-2026-08-22 论文调研：缓解中途重新制动的物理依据与重构方向

**背景**：多列长运行（6000步）超速117 bug 的 3 种补丁修复均陷入"掉速+车钩力爆炸 vs 超速"两难。查论文库（樊运新/李蔚/刘博阳/张二田/王宏宇）+ scholar 检索，寻找物理依据和解决方向。

**结论 1：无现成方案**。无任何论文直接处理"缓解中途重新制动"的状态机交互（中英文检索均无直接命中）。

**结论 2：论文提供物理依据和模型方向**：

- **樊运新（2024 循环制动）**：空气制动用**气体流动理论一维管道模型**（等温 N-S 方程）——制动/缓解是**列车管压力的连续渐变**（减压=制动、充风=缓解），制动力由制动缸压力 pz 决定。**缓解=充风、pz 渐进下降**。**缓解中途可继续施加电制动**（"从控机车为保证列车管再充风时间，继续施加电制动力"）。缓解延时 5.63-13.66s（3万吨）。缓解不同步是纵向冲动主因。

- **李蔚（2023 联合制动）**：制动波/缓解波经列车管压力波传播（有限波速），制动不同步是纵向冲动主因。解决"多源制动时序协调"，非"缓解中途制动"。

**结论 3：重构方向（关键）**：

- 我们的 bug 根因 = **分离状态机**（`_air_brake_active` + `_air_brake_releasing` + `_air_brake_release_frac` 三标志互相阻塞）→ "缓解中途制动被 `not active` 跳过"。

- 论文用**单一列车管压力渐变**（樊运新气体流动模型）——缓解和制动是**同一压力连续升降**，天然无阻塞。缓解中途制动 = 压力从下降转上升（自然打断）。

- **正确解决方向 = 模型重构**：从分离状态机 → 单一"缓解-制动压力渐变"（对齐樊运新气体流动模型）。物理正确且无阻塞。

**当前基线**：3000 步论文基线健康（M1 +44200、M3 +45373、低40=0、车钩力892kN、超80≈0.5%），已固化。重构缓解波模型作为后续课题。

### 诊断-2026-08-22 缓解波传播 bug 修复（连续波前并行释放）+ 诚实验证协同增量

**背景**：补 RL baseline 对比时深挖 M1/M3 协同机制，发现**缓解波传播 bug 是 M3 追尾的根因之一**（非纯物理），导致协同增量 +110042 部分建立在 bug 之上。必须修复并诚实验证。

**bug 根因**（`_advance_air_brake_propagation`）：

- 缓解波循环**依赖** **`releasing[i-1]`**（逐节串行），每节 i 等上一节释放 + 自己的独立满 delay（尾部=60步）

- 结果：第 k 节需 \~60k 步才释放（串行累积），缓解传播严重延迟（实测 38 秒才释放 20 节，理论 6 秒）→ 尾部残留满制动 → 拖停列车

- **数学证明**：串行 6000 步 vs 连续波前 60 步，差 100 倍

**修复**（`train.py`）：

- `_reset_air_brake_command`：对每个设置缓解 delay 的节标记 `releasing[j]=True`（缓解波传播中）

- `_advance_air_brake_propagation`：缓解波循环改为 `for i in range(n): if releasing[i] and active[i]` **各节并行独立倒计时**（去掉 releasing\[i-1] 依赖）

- **验证**：缓解波传播 **61 步 = 6.1 秒**（vs 理论 6.1 秒，**1.0x**），提速 100 倍 ✅

### 诊断-2026-08-25 50-seed 可靠性统计检验（Fisher 极显著，论文核心证据）

**背景**：论文核心论点"协同价值=稳健性（从不追尾）"。早期 10-seed 统计显示 reward 均值 t-test 不显著（p=0.13），被误读为"成果无效"。用 50-seed 扩大样本，用**追尾比例**（而非 reward 均值）做统计检验，证明可靠性差异极显著。

**数据（50-seed 随机化初态，3列，朔黄线）**：

- **M1（协同）：0/50 追尾（0%）**

- **M3（独立）：17/50 追尾（34%）**

- 追尾步数：M1 0.0±0.0 vs M3 44.6±74.0

**统计检验（决定性）**：

| 检验                    | 结果               | 显著    |
| :-------------------- | :--------------- | :---- |
| **Fisher 精确检验（追尾比例）** | **p = 0.000003** | ✅ 极显著 |
| 卡方检验                  | p = 0.00002      | ✅ 极显著 |
| 追尾步数 Welch t-test     | p = 0.0001       | ✅     |
| 追尾步数 Mann-Whitney     | p = 0.000008     | ✅     |

**关键结论（回应用户"成果无效"担忧）**：

1. **M1 从不追尾（0/50）vs M3 34% 概率追尾，Fisher p<0.00001——可靠性差异是统计上铁证**。
2. **reward 均值不显著（p=0.13）是诚实负结果，但非"没效果"**：M3 的高方差来自部分 seed 追尾暴跌（reward 崩到≈-30k），M1 从不出现这种灾难。协同价值 = 消除追尾尾部风险，而非均匀提升速度。

### 设计留痕-2026-08-30 对比/消融实验重构（用户评审后锁定）

**触发**：用户评审实验设计，指出三类问题——①对比与消融两组共用方法（M3/M-DQN-fair 两处重复）；②对比缺"传统方法"创新性锚点（无 MPC 等模型驱动控制）；③消融中 M2 车钩力擦除（与 M1 一致、无信息量）、课程学习消融属训练技巧非创新点。

**锁定决策（用户确认）**：

### 诊断-2026-09-04-代码审计：MARL 协同为何迭代不出增量结果（控制权+奖励+一致性根因）
- **目的**：回答"为什么 M1（分层 MARL 协同）在修复后物理下无 reward 增量、甚至 < M3（独立）"——从控制器/动作/奖励机制逐层定位，区分"训练没学好"与"机制本身无增量"两类根因。
- **方法**：纯代码审计 + 已有数值证据（上节鲁棒性表 + B 机制 reward 分解 + `outputs/diagnostics/coor_policy_report.md`），不重跑训练。

#### 根因1：协同动作控制权过小 = 微观"学无可学"（新定位，最致命）
- 链路：[`hierarchical_controller.py` L37-39/78](file:///D:/Code/MultiAgent/traffic_rl_project/src/controllers/hierarchical_controller.py#L37-L39)：`adj = clip(coor_adj)·adj_coef·COOP_LIMIT`，`COOP_LIMIT=5km/h`。M1 训练用 `--adj_coef 0.1` → **coor_adj=±1 仅把 v_max/v_min 阈值偏移 ±0.5 km/h**。
- 阈值带宽 = v_max−v_min = **40 km/h**（80−40）→ 协同偏移仅占带宽 **1.25%**；规则循环制动触发点只挪 0.5km/h。
- 后果：`_calculate_reward` 里**所有对 coor_adj 敏感的量**（speed_band ±5/−20、间距趋势、跟丢惩罚）对 ±0.5km/h 阈值偏移几乎无响应 → reward 对动作的梯度 ≈ 0 → RL 学不到"更好的协同"，最优可达状态 ≈ 不协同（M1 best +154,849 ≈ M3 +158,638）。
- 对比铁证：**M4（规则 PID 协同）用 `--adj_coef 0.3`（控制权 3×，转换 ±1.5km/h）** 而 **M1（RL）只用 0.1**。RL 想赢过规则基线，自己却只有规则 1/3 的协同杠杆——结构上就被按在地上。这与 ADR-003（目标速度被物理锁死→学无可学）是**同一病在协同层复发**。

#### 根因2：奖励被低层控速主导，协同项淹没
- `speed_band_reward`（+5/列带内，−20/列带外）占奖励绝对主体，完全由规则循环制动（固定阈值）决定，**与 coor_adj 无关**；M1≈M3 在该项几乎相同（B 机制分解已验证 speed_band +222k 两方法一致）。
- 仅 `gap_reward`/跟丢项对协同敏感，且是**分桶**（±1 区间 / >200m 惩罚）。微小阈值偏移很难稳定地把间距误差搬过桶边界 → 协同信号既弱又有噪声。
- 结果：RL 的最优解就是"什么也不做"维持 M3 的默认阈值——因为任何主动协同都只是引入额外方差，多数被跟丢桶惩罚。

#### 根因3：多智能体一致性难收敛（上节已证，机制层面首个）
- B 机制 reward 分解：灾难全来自 `gap_reward −82.5万`，三列独立输出 `v_coop` 不一致 → 速度不同 → 间距拉开 → 跟丢。**一致性的负耦合惩罚在量级上远超协同正向收益**。
- M3（δ=0）三列天然一致 → 无此问题；M1（RL 学联合阈值）在长时程/多体耦合+安全约束下难以找到"三列一致的阈值组合"，探索即破坏一致性。文献（Zhang2024/Liu2021/Wang2025）都是**单列单智能体控速，无列间一致性维度**，故易学；多列群组 MARL 好结果的（Guo2025/车队）多为**质点简化、忽略车钩力**模型。

#### 根因4：阈值偏移方向/结构不合理（机制设计层）
- `adj` 同时加在 `v_max_adj` 和 `v_min_adj` 上 → **只是整带平移、带宽不变**（40km/h 恒定）。它只能挪动"整条速度带"的相位，无法压缩/拉伸循环周期、也无法直接定向一个目标间距。
- 各列跑同一阈值带+同一坡面 → 制动/缓解相位天然被共同坡面锁死（同频），可利用的相位自由度极少。协同概念在此场景"几乎无物可协"（间距健康时无增量必要，间距危险时该类弱动作又够不着）。
- 佐证：[`coor_policy_report.md`](file:///D:/Code/MultiAgent/traffic_rl_project/outputs/diagnostics/coor_policy_report.md) 显示已学 coor_adj 大量贴 clip 界（±0.9，std 0.7-0.8），corr(gap)=−0.642 / corr(dv)=+0.427——**RL 学到的是"间距/速度差→阈值偏移"的粗粒 bang-bang 版启发式，正是 M4 规则 PID 已实现的映射，且权威还只有其 1/3**。即 RL 没有学到规则之外的非平凡协同。

#### 结论（期望 vs 实际）与启示
- **期望**：训练调参/加机制后 M1 应逼近或超越 M3。**实际**：根因1（控制权 1.25%）+ 根因2（奖励主导项与协同正交）+ 根因3（一致性负耦合）共同导致"MARL 协同既学不出增量，最优也仅是复刻默认阈值"。根因1/4 是**机制性**（非训练资源问题），加训练时长/算力无法解决；根因2/3 是**任务难度**（一致性+弱信号）。
- **启示（供决策选向参考）**：①在"A 机制阈值二维 + 0.1 权重"框架内继续迭代 MARL **结构性没戏**——要么把协同杠杆放大到与 M4 同级（adj_coef≥0.3 且让 RL 学非均匀偏移/带宽容积），要么换"真能影响物理"的动作（如多机车电空分工 ADR-009，动作直接作用牵引/制动源）；②"实时性/部署优势"（方向①）不受以上任何根因影响，是独立成立的卖点。
- **留痕来源**：本审计代码行 + 上节鲁棒性表 + B 机制 reward 分解 + coor_policy_report。
