## 三、未完成待办（按优先级）

### ① 司机经验 = 涌现协同 的重新立论（论文战略，讨论完待落盘）⚠️ 重要

**核心矛盾**：导师方向"MPC 无法加入司机经验"，但给 MPC 加了 rule 层后该条被削弱；且 rule 层 ≠ 司机经验。
**已澄清的结论**（[RESEARCH\_POSITIONING.md](file:///D:/Code/MultiAgent/traffic_rl_project/docs/RESEARCH_POSITIONING.md#L67) §1.3.1 待扩展）：

- **rule 层 = 单车安全先验**（限速/车钩力/间距）——谁都能加，MPC 也能加。

- **司机经验 = 跨机车/跨列的涌现协同**（错峰缓解时机、波动缓冲、坡道情境节奏）——MPC 每步重解优化、无时机/情境概念，结构性学不了。

- **创新点正确表述**（避免跑偏）："MARL 在单车安全 rule 之上**学习涌现协同**"，而非"用 DNN 学司机操作"（后者变回归问题会跑偏）。

- **获取模糊经验的机制**：**Reward Shaping**（把"V字坡谷段惰行"编码为带符号奖励偏置 `+λ·I(谷段∧惰行)`），不是 hard code 成 rule。MPC 无法表述"偏好"只能表述"约束" → 这是 MARL 相对 MPC 的结构性差异。

- **待办**：把上述立论 + 3 个协同形态（错峰时机/波动缓冲/坡道情境）写成 `RESEARCH_POSITIONING.md`/论文 Abstract+Contributions。

### ② 评估指标改动：追尾项 → 触发 ATP 制动（用户已提出，未改代码）

- **动机**：有 ETCS/ATP 兜底，追尾（collision\_steps，gap<5m）几乎恒 0，失去区分度；改用"ATP 触发制动次数"更敏感（ATP 介入越频繁 = 越贴限界）。

- **现状**：`collision_steps` = `(gap_arr<5.0).sum()`（[evaluate\_m1\_m3\_long.py L242](file:///D:/Code/MultiAgent/traffic_rl_project/src/evaluation/evaluate_m1_m3_long.py#L242)）。

- **safety\_layer 已有事件机制**：`last_events`（`_log` 记录 `rule='etcs_ebi'/'etcs_permitted'/...`），ETCS 触发有 `etcs_ebi`（紧急制动介入）。

- **待实施**：

  1. 在 fleet env 的 env.step → info 里暴露"本步 ATP/ETCS 触发数"（从 trains\[i].safety.last\_events 数 `etcs_ebi` + 反应式限速触发）

  3. `summarize` 标签从"追尾步数"改"ATP 触发步数"
