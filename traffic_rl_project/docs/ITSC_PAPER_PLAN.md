## 〇、研究问题（RQ）—— 单一聚焦

**主 RQ**：在**长大下坡**场景下，多列**虚拟编组**的重载列车群组，能否通过**分层 MARL** 实现协同控制，使得**列间安全间距、速度一致性和列内车钩力约束**同时得到满足——相比"忽略车钩力的群组控制"和"单列独立控制"，在**不牺牲安全的前提下**显著降低车钩力峰值/超限风险？

**为什么是这个问题**：
- 现有长大下坡 RL（Zhang2024 DQN / Liu2021 DDQN / Wang2025 DQN）**单列 + 忽略车钩力**
- 现有虚拟编组 MARL（Zhang2021 / Song2026 / Guo2025）**多列 + 忽略车钩力**
- **交叉空白**：多列虚拟编组 + 长大下坡循环制动 + 显式车钩力 —— 无人做过

**副 RQ（支撑主 RQ）**：
- RQ1：车钩力约束在"多列群组协同"下是否比"单列独立"更重要？（缺口3的因果链）
- RQ2：协同带来的增量价值是否显著优于"每列独立控制"？（缺口2）
- RQ3：如果群组控制忽略车钩力，是否会给出"速度同步但车钩力超限"的危险解？（对比公平性）

### 0.1 最直接对标：Yang2025（ITSC 2025）【文献调研 08-16 补充】

**Yang2025《Automatic Train Operation of Heavy-Haul Trains Based on Model Predictive Control》**
- DOI：`10.1109/ITSC60802.2025.11423746`（ITSC 2025，已投稿会议同届）
- **同会议、同场景、同目标，算法不同** → 最强对标
- 多质点 20000吨 + **朔黄线真实数据 + 循环空气制动** + **MPC 速度跟踪**
- 目标：**降低车钩力冲动 + 能耗 + 速度跟踪精度**
- **差异**：Yang2025 用 MPC（单列），我们用 **MARL（多列虚拟编组）**

**定位强化**：
- Yang2025 = **单列 MPC + 朔黄线 + 车钩力冲动** → 我们可比（单列场景：MPC vs 我们的列内执行/第1层）
- 我们 = **多列虚拟编组 + MARL + 车钩力** → 多列协同是 Yang2025 没有的扩展
- 论文 Related Work 必须引用 Yang2025，并明确"我们在其基础上扩展到多列协同 + 无模型 MARL"

**Wang2025（ICIRT 2025）**：DQN + 简化动力学 + 循环制动，最大拉力 -9.64%、最大压力 -28.77%（单列 DQN baseline）
**Hu2025（30000吨制动位置）**：1/3-2/3 列车在坡上时制动 → 车钩力最大 → 可用于验证"制动相位错开放大车钩力"机制

## 一、核心贡献（单一创新点）

> ITSC 是短会议论文（6页双栏）。**只讲一个核心贡献**，其他作为支撑。

**核心贡献**：提出一种**显式建模车钩力的分层 MARL 框架**，用于**长大下坡下多列虚拟编组重载列车的协同控制**。

具体支撑（3 点，不是并列创新，而是同一个贡献的三层证明）：
1. **C1（方法）**：分层 MARL 框架——列间 MAPPO（每列=1智能体，协同决策）+ 列内安全执行器（保证车钩力≤1000kN）。对齐 VCTS/魏咪分层范式，但**显式建模车钩力**（现有 VCTS MARL 忽略）
2. **C2（物理）**：在朔黄线真实剖面循环制动下，**车钩力成为群组协同的活跃约束**——不同列循环制动相位错开，列间协同制动不同步会放大列内冲动（已冒烟验证相位错开成立）
3. **C3（验证）**：通过**同架构消融**证明"考虑 vs 忽略车钩力"的群组控制差异显著，且**优于单列独立控制**——严格归因到"车钩力建模 + 协同"而非"算法优势"

## 二、方法架构（对齐论文范式）

### 2.1 分层框架

```
┌──────────────────────────────────────────────────┐
│ 层级一（列间，Platoon Level）—— MAPPO，每列=1智能体   │
│   状态   = 该列 速度/间距误差/前方坡度/车钩力统计     │
│   动作   = 该列目标加速度 a ∈ [-1,1]·max_accel      │
│           （对齐 Zhang2021 动作=加速度）            │
│   奖励   = 限速区间[40,80] + 间距保持 + 速度一致性     │
│            + 避免追尾势场 + 车钩力约束              │
│           ↓ 生成每列"目标加速度"                    │
│ 层级二（列内，Coupler Level）—— 安全执行器           │
│   输入   = 层级一的目标加速度                       │
│   执行   = 目标加速度 → throttle（对齐 Zhang2021）   │
│   约束   = 车钩力安全层 ≤1000kN（对称拦牵引/制动）    │
│           ↓ 反馈实际车钩力给层级一作 obs/reward     │
└──────────────────────────────────────────────────┘
```

### 2.2 关键设计决策（论文导向）

| 决策 | 选择 | 理由 |
|:--|:--|:--|
| 列间动作 | **目标加速度** | 对齐 Zhang2021（动作=加速度）、Hua2024；直接影响物理，有真实梯度 |
| 列内执行 | **安全执行器**（目标加速度→throttle + 车钩力安全层） | 对齐 Zhang2021 列内动力学执行；车钩力由安全层兜底 |
| 虚拟耦合 | **无线协同，无物理车钩** | 对齐 Zhang2021（virtual coupler 第58行）；车钩力只在列内 |
| 限速区间 | **[40,80] km/h**（缓解40/线路限速80，V5.24 修正） | 依据 Zhang2024（朔黄线23.8km长大下坡）：上限80=朔黄线实际线路限速，下限40=重载最小缓解速度；行业《重载铁路设计规范》设计速度≤100/80级。弃用[45,65]（樊运新3万吨参数，与1万吨对象不符+物理不可行） |
| 场景 | **朔黄线真实剖面 shuozhou_23800** | 坡度交替→循环制动→相位错开（已冒烟验证） |
| 扰动 | **不引入人为扰动** | 真实线路本身驱动协同（用户确认） |
| 循环制动 | **RL 学出来的行为**（非规则控制器） | 对齐论文范式；规则循环制动作评估 baseline |

## 三、对比矩阵（补齐缺口1：公平性）

**核心原则**：方法（考虑车钩力的群组 MAPPO）与各 baseline 之间，**只变一个变量**，才能严格归因。

| # | 方法 | 控制器结构 | 信息可用性 | 车钩力约束 | 对比什么 |
|:--|:--|:--|:--|:--|:--|
| **M1** | **提出方法**：群组 MAPPO + 车钩力约束 + 车钩力安全层 | 列间MAPPO + 列内安全执行器 | 每列obs含车钩力 | ✅ | **基线（本文方法）** |
| M2 | 群组 MAPPO **无车钩力约束**（obs/reward 去掉车钩力 + 安全层关闭） | 同 M1（同架构） | obs 不含车钩力 | ❌ | **创新点1消融**：证明"车钩力建模必要性" |
| M3 | **单列独立**（**每列独立训练的单列 MAPPO**，隔离协同变量；无列间 obs/奖励） | 同 M1（同架构） | 仅本列，无列间信息 | ✅ | **创新点2消融**：证明"协同增量价值" |
| M4 | 规则循环制动（验证过的 cyclic_brake_controller，无 RL） | 规则控制器 | 仅本列速度 | ✅ | 对照 RL 学习价值（可选） |
| M5 | **Yang2025 MPC 参考**（单列朔黄线循环制动，ITSC 2025 对标）——**降级为性能参考线，非必复现**（MPC 实现复杂且单列，与多列不完全可比） | MPC 速度跟踪 | 单列 | ✅ | **论文对标**：引用其报告数据（速度跟踪2.67%、车钩力降）作参考线 |
| M6 | **Wang2025 DQN**（单列循环制动+车钩力，ICIRT） | DQN | 单列 | ✅ | **论文对标**：DQN vs 我们的列内，报告最大拉力-9.64%/压力-28.77% |

**M3 定义明确（读论文后修正）**：M3 = **每列独立训练的单列 MAPPO**（非"群组网络去列间obs"，后者会混入多智能体网络结构差异）。但需注意：若真实剖面下每列本身能靠循环制动独立控制好，协同增量可能小（Guo2025 汽车编队间距降8.3%的机制未必适用于重载）。**H1 需真实数据验证**，若协同无增量则回决策层。

**公平性保证**：
- M1 vs M2：**完全同架构**，只变"是否考虑车钩力"（`use_coupler_constraint` 开关已实现）→ 差异严格归因到车钩力建模
- M1 vs M3：M3 用**相同 MAPPO + 相同安全执行器**，但每列独立（无列间信息/无协同）→ 差异归因到协同
- 所有方法：**相同随机种子、相同训练步数、相同评估协议**

## 四、实验协议（补齐缺口2/3 + 严谨性）

### 4.1 训练协议（可复现）

- **多种子**：5 个独立训练种子（seed 0-4），报告 mean±std（避免单 seed 假象，V5.13 教训）
- **训练步数**：足够收敛（先做收敛曲线，找到拐点，再定总步数；不盲目长训）
- **固定配置**：lr、entropy、batch_size、GAE 等超参在对比方法间**完全一致**
- **checkpoint 策略**：保存 best 模型（训练 reward 最优），评估报告 best 非末 ep（V5.14 教训）

### 4.2 评估协议（严谨）

- **评估种子**：独立于训练种子的 N 个评估种子（随机化初始状态/扰动工况）
- **确定性评估**：策略 eval 模式（无探索噪声）
- **关键指标**（每列逐一记录，不只记均值——论文对比需要分组明细）：
  - 车钩力峰值（kN）/ 超限次数
  - 速度一致性（各列速度 std）/ 速度范围是否在 [40,80]（V5.24）
  - 间距误差（m）/ 最小间距（安全）
  - 能耗（kWh）（可选，因下坡能耗低）
  - 奖励曲线（训练收敛性）

### 4.3 假设检验（补齐缺口2/3 的因果链）

**缺口2（协同增量价值）**：对比 M1 vs M3
- 假设 H1：M1 的间距误差/速度一致性显著优于 M3（协同保持编队）
- **若 H1 不成立**（协同无增量）→ 需重新设计列间 obs/reward 或场景（不能硬做）

**缺口3（车钩力因果链）**：对比 M1 vs M2，且分单列/群组两个场景
- 假设 H2：群组场景下，M1 vs M2 的车钩力峰值/超限差异 > 单列场景下 M1 vs M2 的差异
- 即：**车钩力约束的价值在群组协同下更突出**
- **机制核心（读论文后强化）**：多篇论文一致指出**"缓解不同步"比"制动不同步"更危险**——张二田(朔黄线实测"缓解后车钩力最大")、刘博阳(缓解同步性↑→拉钩力降44.5%)、王宏宇("最大车钩力在缓解后，先拉后压")、李蔚("制动不同步→前堵后涌")。因此第2层协同的增量价值**最可能体现在"协同缓解时机"**（避免缓解不同步），而非仅"协同制动"
- **H2 检验**：观察群组协同下"缓解阶段"车钩力 vs 单列独立"缓解阶段"车钩力，验证协同缓解是否显著降车钩力
- 若 H2 不成立 → 车钩力仍是"单列安全兜底"，需构造更强协同压力场景

## 五、仿真器验证（补齐缺口 + 论文可信度）

**原则**：我们的多体模型（完整多体 + 车钩力）与 Zhang2024（简化单质点、忽略车厢间力）**模型架构不同，不强制对齐数值**。只对齐"场景 + 物理行为"。论文用**物理规律自证**我们的模型真实性。

**已对标论文（物理规律层）**：

| 验证项 | 对标论文 | 关键数据/规律 |
|:--|:--|:--|
| 制动减压-压钩力 | Zhang2025 | 50/70/100kPa → +16.8%/+36.8%（已有 ✅） |
| 车钩间隙-车钩力 | 杨敏 | 0.01 vs 0.018m 差 52.14kN（已有 ✅） |

**我们多体模型的物理自洽验证目标（E2 核心）**：
1. **惰行下坡会加速**（-10.5‰ 平衡速度 ~152km/h）→ 需循环制动，这是长大下坡真实特征
2. **循环制动能把速度控制在 [40,80] km/h** → 证明控制有效（V5.24 对齐 Zhang2024 朔黄线[40,80]：上限80=线路限速，下限40=最小缓解速度；行业/物理三重依据）
3. **制动相位错开会放大车钩力** → 证明"车钩力是协同瓶颈"机制
4. **车钩力有物理合理量级**（峰值 <1000kN 正常工作）→ 证明多体动力学正确

**不强制对齐**：不调 Davis 阻力去复现 Zhang2024 的 65 km/h 平衡速度（模型不同，参数天然不同）。
