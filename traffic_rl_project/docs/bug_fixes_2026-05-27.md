## Bug 1: Episode 在第1步后立即终止

### 现象
训练脚本运行后，每个 episode 在第1步就被截断（truncated=True），导致无法进行有效训练。

### 根因
`MultiHoverAviary._computeTruncated()` 方法中的位置限制条件过于严格：

```python
# 原始代码
if (abs(states[i][0]) > 2.0 or abs(states[i][1]) > 2.0 ...
```

编队控制环境中无人机的起始位置距离较远（x=5.0, x=10.0），远超2.0米限制，导致每个 episode 第一步就触发截断。

### 修复
修改 `gym_pybullet_drones/gym_pybullet_drones/envs/MultiHoverAviary.py`，放宽位置限制：

```python
# 修复后
if (abs(states[i][0]) > 20.0 or abs(states[i][1]) > 20.0 or states[i][2] > 5.0
```

## Bug 2: PPO 动作形状不匹配

### 现象
PPO 的 `update()` 方法抛出 `ValueError`：期望动作维度为 12（flatten），实际为 4（单个无人机动作维度）。

### 根因
训练脚本在存储 transition 时，存储的是 `reshape` 后的动作（形状 `[3, 4]`），而 PPO 算法期望的是 `flatten` 后的动作（形状 `[12]`）。

### 修复
在 `agent_lightning_train.py` 和 `agent_lightning_integration.py` 中，引入 `original_action` 变量保存 flatten 动作：

```python
original_action = action.copy()  # 保存原始 flatten 动作

if len(env.action_space.shape) == 2:
    action = action.reshape(env.num_drones, env.action_space.shape[1])
else:
    action = action.reshape(env.num_drones, 4)

# 传递给环境的是 reshape 动作
rpm_action = HOVER_RPM * (1 + 0.05 * action)
next_state, reward, terminated, truncated, info = env.step(rpm_action)

# 存储的是原始 flatten 动作
agent.store_transition(flattened_state, original_action, reward, log_prob, done, value)
```

## Bug 3: PPO update() 缺少动作维度检查

### 现象
训练在错误状态下持续运行，用户无法及时发现动作形状问题。

### 修复
在 `optimized_ppo.py` 的 `update()` 方法中添加动作形状断言：

```python
if len(actions.shape) > 2:
    raise ValueError(
        f"动作形状错误！期望形状 [batch_size, {expected_action_dim}]，"
        f"实际形状 {actions.shape}。请检查存储的是否是flatten后的动作。"
    )
if actions.shape[-1] != expected_action_dim:
    raise ValueError(
        f"动作维度错误！期望维度 {expected_action_dim}，实际维度 {actions.shape[-1]}。"
    )
```

## Bug 4: 训练脚本日志完全无输出

### 现象
运行训练脚本后长时间没有任何日志输出，无法判断训练进度。

### 根因
Python `logging` 模块默认级别为 `WARNING`，而训练脚本使用 `logger.info()` 输出。未调用 `logging.basicConfig()` 配置日志级别。

### 修复
在 `agent_lightning_train.py` 开头添加日志配置：

```python
logging.basicConfig(
    level=logging.INFO,
    format='%(message)s',
    handlers=[logging.StreamHandler(sys.stderr)]
)
sys.stderr = os.fdopen(sys.stderr.fileno(), 'w', buffering=1)

# 抑制第三方库冗余日志
logging.getLogger('agentlightning').setLevel(logging.WARNING)
logging.getLogger('agentlightning.runner').setLevel(logging.ERROR)
logging.getLogger('agentlightning.trainer').setLevel(logging.ERROR)
logging.getLogger('agentlightning.execution').setLevel(logging.ERROR)
```

## Bug 5: Trainer.fit() 永不返回（核心问题）

### 现象
训练完成所有 episode 后，脚本挂起永不退出。需要手动 Ctrl+C 才能终止。`trainer.fit()` 调用永远阻塞。

### 根因分析

Agent Lightning 的 `SharedMemoryExecutionStrategy` 有两种运行模式：

#### 配置: `main_thread="runner"`（问题配置）

```
主线程:  Runner (处理 rollouts)
后台线程: Algorithm (Baseline - 调度 rollouts)
```

`_run_algorithm` 源码（shared_memory.py:163-177）：

```python
def _run_algorithm(self, algorithm, store, stop_evt, thread_exceptions):
    try:
        asyncio.run(self._run_until_completed_or_canceled(
            algorithm(store, stop_evt), stop_evt))
    except asyncio.CancelledError:
        logger.info("Algorithm bundle canceled due to stop signal.")
    except BaseException as exc:
        # 仅在异常时设置 stop_evt！
        stop_evt.set()
        raise
    # 正常完成时：不设置 stop_evt ← BUG 根源
```

Runner 的 `iter()` 循环依赖 `event.is_set()` 退出：

```python
while not (event is not None and event.is_set()) and (...):
    # 轮询 rollout
```

**致命缺陷**：Baseline 算法正常结束时不设置 `stop_evt`，导致 Runner 在主线程上永远轮询，无法退出。

#### 配置: `main_thread="algorithm"`（正确配置）

```
主线程:  Algorithm (Baseline)
后台线程: Runner (处理 rollouts, daemon)
```

`execute()` 源码（shared_memory.py:233-241）：

```python
if self.main_thread == "algorithm":
    # Runner 在 daemon 线程中
    for i in range(self.n_runners):
        thread = make_thread(...)
    
    # Algorithm 在主线程上运行
    self._run_algorithm(algorithm, ...)
    
    # Algorithm 完成后主动设置停止信号
    stop_evt.set()  # ← 正确通知所有 Runner 退出
```

### 修复

**仅改动一行** - `agent_lightning_integration.py`：

```python
# 修复前
strategy=SharedMemoryExecutionStrategy(n_runners=1, main_thread="runner"),

# 修复后
strategy=SharedMemoryExecutionStrategy(n_runners=1, main_thread="algorithm"),
```

### 影响说明

- `main_thread="algorithm"` 下 Runner 运行在 daemon 线程中
- PyBullet 物理仿真（DIRECT 模式，无 GUI）在线程中运行完全正常
- Runner 是 daemon 线程，主线程退出时自动清理，无需手动 join

---

## 预防规则

1. **Agent Lightning `SharedMemoryExecutionStrategy` 始终使用 `main_thread="algorithm"`**
   - 这是唯一能保证正常退出的配置
   - 除非 Runner 需要主线程权限（如 GUI），否则不应使用 `main_thread="runner"`

2. **训练脚本必须配置 logging**
   - `logging.basicConfig(level=logging.INFO)` 是必须的
   - 第三方库应抑制为 WARNING 或 ERROR 级别

3. **动作存储必须使用 flatten 格式**
   - 环境交互用 reshape 动作
   - Transition 存储用 flatten 动作
   - PPO update 中检查动作维度

4. **仿真环境截断条件应与任务目标匹配**
   - 编队控制需要更大的活动空间
   - 修改截断阈值前先确认无人机起始位置范围
