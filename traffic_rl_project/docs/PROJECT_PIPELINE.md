## 三、通用开发流程（两个阶段共用）

每阶段遵循同一套方法论，后续任何新任务（列车编队）按此流程执行：

```
① 文献调研        → 明确物理模型与算法选型的依据
② MDP 建模        → 定义状态 / 动作 / 奖励函数
③ 环境搭建        → 基于专业仿真器封装 Gym 接口（禁止手动/mock 环境）
④ 基线训练        → 先用成熟算法跑通链路，验证环境与奖励合理性
⑤ 算法适配        → 按任务特性选型（多智能体用 CTDE）
⑥ 奖励与超参迭代  → 一次只改一个变量，记录结果
⑦ 评估与消融      → 确定性推理、组件贡献度分析
⑧ 成果固化        → 报告 + 检查点 + 图表 + 配置快照
```

**每阶段的验收标准**：训练收敛稳定（无策略坍缩）→ 指标达到阈值 → 消融实验说明组件贡献 → 报告可复现。

**核心定位（用户多次强调，绝不允许改动）**：
- 论文题目：面向长大下坡场景基于多智能体强化学习的**重载列车群组自动控制方法**
- 三大支柱：**循环制动 + 多列群组协同 + 车钩力约束**（分层 MARL）
- 现有长大下坡 RL 工作（Zhang2024/Liu2021/Wang2025）均忽略车钩力 → 本项目的创新空间

**正确场景理解（2026-08-20 用户最后纠正，关键）**：
- ❌ **不是**"更紧间距制造压力"或"系统强制制动制造车钩力压力"——这是此前多次失败（协同价值=0）的根源
- ✅ **正确逻辑**：朔黄线长大下坡**天然需要循环制动**（单列本身产生车钩力）+ **多列车需保持安全间距**（虚拟耦合）**双重需求天然并存**
- 各列循环制动**相位天然错开**，跟随车为保持间距需**配合前列的制动/缓解节奏** → 协同价值由**场景天然驱动**
- **不引入人为扰动**（真实线路本身驱动协同）

**必须验证的增量（下一阶段核心任务）**：
- **M1（多列群组协同 + 车钩力约束）** vs **M3（单列独立，只循环制动不协同）**
- 证明 M1 相对 M3 的**增量价值**（间距保持 + 安全，车钩力作为贯穿约束）
- 场景：朔黄线 `shuozhou_23800` 真实剖面 + 多列虚拟耦合 + 长大下坡循环制动

**已完成的关键积累（支撑本方针，勿推翻）**：
- 缓解波传播 bug 已修复（缓解波物理保留），朔黄线 + 1+0 单机 + 循环制动车钩力 740kN 守住
- 分层框架：层级二 RL 第1层策略控速（warm start 自规则）+ 层级一 δ 协同（E18 avg+2.1万稳定）
- 限速区间 [40,80]（行业 + 论文 + 物理三重依据）
- 离散档位动作 + 规则循环制动 warm start + 循环引导

**工作方针执行检查表（每项工作前对照）**：
1. 场景是否为"朔黄线真实剖面 + 多列保持间距 + 循环制动"天然驱动？
2. 是否引入了人为扰动？（→ 应改为天然驱动）
3. 对比是否锚定 M1 vs M3（协同增量）？
4. 车钩力是否作为贯穿约束（而非人为制造超限）？

**核心逻辑链澄清（2026-08-20 用户纠正，务必记住，勿再搞混）**：
- ① **车钩力在列内处理**（每列内部车厢间机械钩缓，制动-缓解产生）——**不冲突**
- ② **编队的价值 = 维持各列之间距离**，而维持距离需要**循环制动**（长大下坡必须制动控速）
- ③ **编队 → 循环制动 → 列内车钩力变化**：一列为配合编队距离而制动/缓解 → 该列内部车钩力变化
- ④ **核心创新 = 多列编队协同（为保持间距的循环制动节奏配合）影响/约束每列内部车钩力**
- **"错开"为何相关**：各列循环制动相位/节奏不同（前列先制动、后列配合）→ 某列因配合间距急制动 → 列内车钩力放大；**协同价值 = 保持间距的同时控制/最小化每列车钩力**
- **正确对比**：M1（协同协调制动节奏保持间距 + 控车钩力） vs M3（每列独立按速度循环制动，不管间距 → 追尾急制动 → 车钩力大/牺牲速度）
- **与 Zhang2024 区别**：Zhang2024 单列循环制动，无"保持编队距离"约束；**我们的创新 = 在"多列必须保持间距"约束下协同循环制动，同时守住每列车钩力**
- ⚠️ **勿把车钩力当成"多列之间"机械耦合**（会陷入"多列无机械钩挂"的困惑）；实际是"多列协同→影响每列循环制动节奏→影响该列内部车钩力"

### 4.2.6 速度维持优化计划（低40掉速瓶颈，2026-08-21，当前执行）

**背景**：步骤③评估显示 M1/M3 低40占 26%（掉速惩罚重），整体 reward 为负。这是当前唯一阻塞 M1 vs M3 增量"净为正"的瓶颈。修复编码根因后，协同增量已由负转正（M1 -10123 vs M3 -13407），但**速度维持不足**使整体 reward 仍为负，无法作为论文正向结果。

**根因分析（低40掉速）**：
- `get_action_cyclic_braking` 用 `v_min=40km/h` 作为缓解触发阈值（`vel <= eff_v_min` 才缓解）
- 万吨列车在长大下坡（-10‰）上，一旦开始制动，**缓解后因下坡重力惯性继续减速穿越 40km/h**（缓解是渐变衰减需时间 + 缓解后 release_throttle=0 惰行，重力仍拖动）
- 第1层 RL 策略（warm start 自规则）学的缓解时机可能偏晚，未在跌到 40 前及时缓解

**优化方案（3 条，按预期收益/风险排序）**：

| 方案 | 内容 | 预期收益 | 风险 | 优先级 |
|:--|:--|:--|:--|:--|
| A | **提前缓解阈值**：v_min 触发缓解改为 `v_min + margin`（如 40→48km/h），让速度在跌到 40 前就缓解 | 直接降低40占比 | 循环制动区间变窄，制动更频繁（需验证车钩力） | 高 |
| B | **缓解时加小牵引**：release_throttle 从 0 改为 0.3 小牵引，对抗下坡减速 | 缓解后不掉速 | 长大下坡牵引可能超速（有 80 上限兜底） | 高 |
| C | **奖励塑形**：speed_band 对低40惩罚从 -20 降为 -10（低40是效率问题非安全），或对"接近40及时缓解"给正向 | 降低 reward 惩罚拖累 | 可能让 RL 学会贴低40滑行 | 中 |

**验证流程**：
1. 先用**规则循环制动**（非 RL）在单列上验证方案 A/B/C 对低40占比和车钩力的影响（快，秒级）
2. 选最优方案组合，验证不破坏车钩力 ≤1000kN、速度范围
3. 若方案涉及第1层 RL 策略（缓解时机），需重训第1层 → 重训第2层 → 重评估（慢）
4. 若方案是纯参数/奖励调整（不涉及 RL 学习），可直接改评估脚本重评估（快）

**执行顺序**：先做 1（规则验证，快）→ 判定方案 → 需要则走完整重训链（3）或直接重评估（4）。

### 4.2.7 多列长运行满制动失效专攻计划（2026-08-21，当前专攻）

**背景**：方案A后健康场景固化（M1 +44200、低40=0、车钩力892kN），但扩展评估到 6000 步（列车走13km）时，速度飙到 **117km/h**（超80上限），且**多列满制动不减速**。

**已确认事实**（详见 VALIDATION_BASELINE「诊断-2026-08-21 长距离超速」）：
1. 限速安全层配置正确（max_speed=80km/h），超速时 protect 强制制动（已修 -0.75），第1层策略输出满制动 -1.0
2. **fresh 状态**下单列 vs 多列满制动**表现一致**（都 95→80 减速）→ 多列动力学本身无 bug
3. **长运行后（4100步 δ=0）**多列满制动失效（95→96 加速），单列仍减速（95→84）→ **状态积累问题**
4. 制动力相关属性（braked_weight_ratio/max_ed_ratio/ab_sources/brake_wave_speed/eot）单列多列全部相同

**核心矛盾**：同一动力学（train.py）、同一配置，长运行后多列满制动失效而单列正常。差异仅在多列 trains[0] 经历长运行（缓解波传播/车钩力状态残留）。

**假设（待验证）**：
- **H1**：缓解波传播状态 `_ab_propagation`/`_release_propagation` 在长运行后残留，导致后续制动命令未正确传播到尾部 → 制动力不足
- **H2**：车钩力-制动力耦合：长运行下车钩力状态（列车被拉伸/压缩）影响制动力应用
- **H3**：dt 积分累积误差 / 数值稳定问题在长运行时放大
- **H4**：坡度查询 bug（长运行时列车横跨多坡段，grade 计算错误导致制动力低估）

**排查步骤（按优先级）**：
1. 在 4100 步长运行后，打印各车厢实际制动力 `_brake_force`、空气制动档位、缓解波传播数组 → 定位是否尾部制动力丢失
2. 对比长运行后 vs fresh 的动力学内部状态（`_ab_propagation`、车钩力、pos）→ 找差异
3. 用**恒定坡度**（排除坡度查询）在长运行后满制动 → 隔离 H4
4. 重置缓解波传播状态后满制动 → 隔离 H1
5. 若定位到状态残留 → 修复（reset 时清空传播状态 / 修正传播逻辑）

**验证目标**：长运行后满制动仍能限速（与 fresh 一致），6000 步不超速到 117。

**检查表**：不引入人为扰动；场景=朔黄线真实剖面+多列；车钩力贯穿约束。

### 下一步计划（2026-08-20 写入，新对话据此继续）

**目标**：证明 **M1（多列协同循环制动保持间距 + 控车钩力）** 相对 **M3（单列独立循环制动，不管间距）** 的增量——在保持间距的同时守住每列车钩力 ≤1000kN。这是论文核心。

**关键前提（已厘清）**：车钩力在列内处理；多列协同通过改变每列循环制动节奏影响列内车钩力。**正确场景 = 朔黄线真实剖面 + 多列保持间距（虚拟耦合）+ 循环制动**，不人为制造坡段错开。

**待办（按优先级）**：
1. ✅ **回退/停用方案A人为坡段错开**（2026-08-20 完成）：移除 `train_fleet_env.py` 的 `start_offset_m`/`spacing_m` 参数 + reset 方案A分支、`train_fleet.py` 的 CLI 参数 + 传入、`evaluate_m1_m3_long.py` 的场景参数。恢复普通场景 reset 布局。**已验证**：各列同坡段起步（队首坡度均为 -0.002‰）、初始速度 65km/h、列间间距 = 动态目标间距（183.3m = 100 + 5×headway）。35 测试通过无回归。
2. **验证正确场景下 M3 是否追尾/车钩力变化**：普通场景 + 各列独立循环制动，观察是否因"不管间距"而追尾/间距漂移/列内车钩力变化 → 确认协同必要性。**（下一步执行）**
3. **确保分层模式车钩力安全钳制生效**（E25C 已修复，需回归验证车钩力 ≤1000kN）。
4. **重训 M1（协同循环制动）对比 M3**：在正确场景下，M1 协同保持间距 + 控车钩力，M3 独立循环制动。对比间距/速度/车钩力增量。
5. **留痕**：结果写入 VALIDATION_BASELINE.md（诊断-日期-主题），含逐列/逐工况数据。

> ⚠️ **方向纠错（2026-08-20，用户纠正）**：此前基于 Zhang2021/Guo2025（地铁/汽车平直场景）提出的 **APF 势场控制器"解耦"重构方案是生搬硬套**，与本项目朔黄线长大下坡 + 循环制动 + 车钩力场景物理不符（APF `tanh(间距误差)+tanh(速度差)` 假设车辆可自由±加减速，而长大下坡无法牵引超速、只能制动降速）。**已废弃该方向，不在重训 M1 时引入 APF 势场控制器**。正确分层 = 列间 RL 宏观协同决策 + 列内规则循环制动 + 车钩力安全层执行（详见 VALIDATION_BASELINE 纠错备注）。

### 4.4 迁移需注意的差异（来自阶段一经验）

| 经验 | 列车场景的对应调整 |
|:--|:--|
| VEL 模式 PID 补偿重力 | 列车无悬停问题，动作直接映射牵引/制动，注意死区与最大牵引率 |
| 编队间距 5 m 目标 | 列车间距约束更硬（安全距离 + 车钩缓冲），奖励权重需重调 |
| 截断条件 x>20 | 列车纵向里程长，需按运行区间设计终止条件 |
| 3 架无人机组队 | 列车 3-6 节车厢，CTDE 的集中 Critic 输入维度随车厢数增长 |
