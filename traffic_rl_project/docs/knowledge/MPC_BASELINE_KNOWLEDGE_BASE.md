## §1 业务背景与核心概念

论文对比实验的唯一 MPC 基线代码 = **NMPCController**（ADR-022；旧 `FairMPCController`/简化 MPC 已删除，历史 MPC 数值作废）。对比口径（ADR-037，废止 ADR-016 Regime A 协议）：不按坡道换 MPC 模型；同一仿真器、同一环境与坡度数据、同档调参力度——坡度是 MPC 预测模型的**固有输入**（图纸天然先于运营存在），**不设"逐线重喂 `grade_at`/在线标定 b0"协议，也不作"免重辨识成本"叙事**；D-RL 跨线严格零微调。立论 = **相对传统基线的编队指标收益**（ADR-042，2026-10-19；旧"编队上下文协同增益"随独立消融废除）。**⚠️ 主表角色已由 ADR-034（2026-10-13）修订：NMPC 退出主表**（related work 文本，"方法与场景不匹配，忠实复现不成立"）；**主表 MPC 行 = Tube MPC**（following Song2026 虚拟编组管式预测控制架构，车钩力口径见 `RESEARCH_POSITIONING.md` §1.2；主对比**同一 MT-2 物理，MPC 侧不建模/不约束车钩力**（原「物理关闭车钩力」口径已由 **ADR-042 附段（2026-11-14）**改述为「控制器侧关闭车钩模型」——零阻抗会把列车解体，判死依据见 §10.3），同仿真器 + 同档调参力度；**只主张编队指标胜出，绝不主张车钩指标胜出**；ADR-042）。

技术构成：casadi + IPOPT；列内**集中质量（lumped）多体**（ADR-022 术语）；MT-2 车钩；坡度经 `grade_at` 接口读入（固有输入，非重喂）。

## §2 核心流程（求解与桥接）

`compute_actions_from_env()`（nmpc_controller.py）：
1. 首次调用按编组构建 casadi 优化问题；
2. 从 env 快照状态、读入 `grade_at` 坡度（固有输入）、设初值；
3. IPOPT 求解，记录 `solve_times` / `solve_statuses`；
4. 输出每列目标加速度，经桥接逻辑反解为规则基线的加性调制 `(ed_mod, ab_mod)`，保证与 D-RL 动作权限一致（与 `inner_rule_cyclic` 公平对比）。

## §6 核心规则与隐藏约束

- **AI pitfall**【状态残留】`--n_seed` 多回合复用同一 env 时，每回合开始必须 `_mpc.reset()`（历史 bug，有回归测试）。
- **AI pitfall**【solve_statuses】读取求解状态用 `getattr` 兜底（缺失不崩溃）；`NMPCController` 负责记录并清空 `solve_statuses`。
- 【唯一基线】只认 `NMPCController` + `--mpc_type nmpc`；任何"简化 MPC/旧 Fair"数值已作废（ADR-022）。
- 【对比口径】同一仿真器/环境/坡度数据/调参力度；坡度为固有输入，**不设逐线重喂与标定协议**（ADR-037）；D-RL 跨线零微调——改对比口径须走 ADR。
- 【权限对齐】MPC 输出经桥接为 `(ed_mod, ab_mod)` 调制，不得直接给原始加速度当动作。
- 【术语】"多体" = 集中质量（lumped）多体（ADR-022）。

### L2 状态构造的三个决定

1. **参考轨迹直接用 `ref_speed_table`**（75 口径表，与 D-RL 同源）——这同时满足"公平标定"（两方法跟同一条参考线）。
2. **车 1 = 领航列，车 2/3 = 跟随列**（x0 的 s_e2/v_e2 是前车实际状态 − 期望间距，Song2026 式 20）。三列 = 3 个 TubeMPC 实例（idx 0/1/2），与 3 智能体 MARL 对称。
3. **起点/编组/工况与 D-RL 完全一致**（4300 m 固定起点、10 kt 1+108、朔黄 49.6 km、主对比关车钩物理——ADR-042）。

### 陷阱清单（NMPC 时代教训，硬红线）

1. **【权限对齐】** Tube MPC 是**独立基线**：û 直接物理执行（thr/ed/notch），**不走 `(ed_mod, ab_mod)` 调制**——NMPC 的 clip 带宽陷阱（MPC 期望 ED [0,0.75] vs 规则基线 [0,1]，455 步越权，ADR-022/044）在调制架构下才存在。
2. **【不比车钩】** 写作红线（ADR-033）：Formation-MPC 显式关车钩约束，**只主张编队指标（列距/速度带）胜出**。
3. **【metadata】** 评估落权威 metadata（AGENTS 红线 5），`--mpc_type tube` + 配置 + 求解器参数全记录。
4. **【ED 下限】** û<0 时 ED 深度映射不得被 `ed_zero_point=0.77` 类钳制——那是 notch 动作空间的参数，MPC 走自己的执行通道。

### 10.2 v2「四问题」复核结论（2026-11-14 11:30）——三项不是缺陷，三项才是

**不得再作为缺陷引用（误判/误读）**：

1. `gap_lead` 前 ~1300 s 的 2465 个 NaN **全部属于无前车的领航列**，两条跟随列全程有限 ⇒ 「列间包络早期失效」不成立，包络公式未改。
2. v2 metadata 是 `coupler=mt2`，1296 kN 不是「零车钩却非零」⇒ fc 语义并无 bug。
3. 「只跑 7395 步就提前终止」是报表误读：**7395 = 2465 决策步 × 3 列**的日志行数；领航列在下一控制步越过 49600 m 后按主环境协议正常截止。已修 `steps`/`full_route`/末速口径并记录三列末位置。

**真根因（v3 已修，改代码前必须知道）**：

1. `cycle_brake` 读取不存在的 `dyn.t`，且把「**缓解后 45 s 充风**」写成「施加 45 s 后缓解」——因果方向反了（现为 `t_now - t_rel >= 45`，施加时长不设上限）。
2. 主循环未每步令 `xbar = x0` ⇒ tube 反馈**重复叠加状态误差**（现由「名义状态重置」单测守住）。
3. MPC 在机车-货车组速度差耦合下可返回近零/正输入，前馈又抵消 AB/坡度分力 ⇒ **超速时反而补牵引**。已加 `speed_guard`：超参考 0.5 m/s ⇒ 零牵引 + 满 ED（与主环境 ATP 兜底语义一致；AB 仍归循环制动状态机）。

- **⚠️ 计数单位也不同源（10× 陷阱，2026-11-19 一手核实）**：`evaluate_decompose.py` 的循环 `for i in range(max_steps)` 每迭代 = **1 个 0.1 s 原始步**（RL 动作每 `decision_interval=10` 迭代才重决策）；`evaluate_mpc_tube.py` 每迭代 = **1 个 1.0 s 控制步**（`DT_MPC=1.0`，内部 `SUB=10` ZOH）。⇒ 同一 49.6 km 全程：RL 侧 n = **23,274 原始步**（=2,327 s），MPC 侧 n = **2,467 控制步**（=2,467 s）。⇒ **所有"步数型"绝对计数（`viol` / `rear_end_steps` / `ab_steps` / `overspeed_car_steps`）在 MPC 行与 RL 行之间不可直接比大小，须先乘 `decision_interval` 统一到"秒"**：MPC 789 穿透 = **789 s**，nincr 576 超限 = **57.6 s**。比值型指标（`band_rate`、`p_ab_applied` 等）无量纲，可直接比。
