# 每日工作日志入口（timeline）

> 工作日志（当天做了什么、卡在哪、踩了什么坑）统一记录在 **`.codebuddy/memory/YYYY-MM-DD.md`**，
> 每日一篇、当天追加、不覆盖**（这是其既有规范，也是工具约定，故不迁移）。本文件是指南针式入口。

## 为什么放 `.codebuddy/memory/`
- 既有约定 + 工具(token 记忆)读取，迁移会破坏工具集成。
- 它承接"**当天流水**"；"**正式结论/数据/决策**"仍按角色写进 `docs/*`（见 rules README 判断树）。

## 每日日志怎么写（最佳实践）
| 段落 | 写什么 |
|---|---|
| 今日目标 | 一行为开头（可对应 PIPELINE 条目）|
| 进展 | 做了什么、跑了什么命令、关键结果数值 |
| 卡点/踩坑 | 简短现象；**正式深层根因走** `docs/logs/learnings/LEARNINGS.md` |
| 明日 / 下一步 | 待办回填到 `PROJECT_PIPELINE.md` 计划 |
