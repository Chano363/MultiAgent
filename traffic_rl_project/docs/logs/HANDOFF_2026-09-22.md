## 1. 当前现状

### 1.1 主线上下文（MPC 是对比基线）

- 论文主 claim（ADR-016）：**免重辨识成本**——零重标定代价的 MARL（D-RL）≈ 逐线重标定后的 MPC。
  只比"谁扛得住部署"，不比"谁控制更准"；MPC 对比**只留 Regime A**（B 已废止）。
- 主训练 53km 的 **5-seed×1400ep 长训在后台跑**（~4.3 天，日志 `outputs/logs_final_parallel/seed{N}.log`）。
  长训完 → 主对比评估。MPC 线的评估实验大部分要等主训练 D-RL 权重就绪才能对齐跑，但**脚本与协议现在就能搭**。

### 1.2 MPC 控制器：结构正确，不要重写 ✅

`src/controllers/fair_mpc_controller.py`（`FairMPCController`，Regime A 公平版）已满足 ADR-016 要求：
- **直接加速度控制**（放弃已证伪的 coor 阈值顾问，回归传统 MPC 形态）
- **控制分块**（B 块 × 每块常加速度）+ 滚动时域 SLSQP
- **显式硬约束**：列间距≥`gap_min`、车钩力代理≤1000kN
- **`grade_at` 前瞻坡度**（公平 MPC 掌握线路图纸，沿预测位置查真实坡度）
- **b0 在线标定**（速度差分残差，使预测首步与实测一致）——免重辨识公平对比的关键
- **`inner_rule_cyclic` 规则内层兜底**（超 v_max 压制、低于 v_min 恢复牵引）——消解"strawman"质疑
- **`solve_times`** 全程记录（限 2=实时性叙事）
- 评估入口已在 `src/evaluation/evaluate_m1_m3_long.py`：`mpc` / `fairmpc` / `mpc_dir` / `mpc_rule`

**结论：控制器代码不用动，改动全在"评估脚本 + 实验跑批 + 结果归档"。**

## 2. MPC 接下来要做的全部工作（详细）

> 顺序：先"脚本/协议"（不占算力，现在就能做）→ 等主训练 D-RL 权重 → 跑评估 → 归档留痕。

### 阶段 A：评估脚本与协议工程（今天可开工，不占算力）

1. **写/校 MPC 评估脚本**，使其对齐当前主线：
   - 剖面：`shuozhou_real_53km`（主表）+ `long_downhill_20km` / `35km`（跨线目标）；23.8km 仅作已知锚
   - 一定是**独立完整剖面**单跑，不是"多段 1200 步拼接"
   - 逐实验 `build_metadata` 内嵌 JSON + 时间戳归档，不覆盖旧文件
2. **实现免重辨识 protocol A 的自动化**：
   - MPC 侧：每条目标线**逐线重喂 `grade_at`** + 在线标定 **b0**（公平标定）
   - D-RL 侧：跨线**严格零微调**，评估脚本里显式输出 "no fine-tuning on target line" 声明到 metadata
   - protocol 身份逐实验标 **A**
3. **补指标采集**：
   - 级联失败率 / MPC SLSQP **求解失败次数**（求解失败→级联判定规则写清）
   - `solve_times` 每步记录 → 汇总分布（均值/p95/超时率）
   - 车钩力峰值 / 超限次数、ATP 触发次数、列距是否破界、限速是否守
4. 复用且校验：评估侧物理配置 = **同一套物理配置对象**（训练/评估单一来源），动作量化与训练一致。

### 阶段 B：跑实验（等主训练 D-RL 权重就绪后）

6. **免重辨识跨线泛化**：20/35km 各跑 D-RL（零微调）vs 公平 MPC（逐线重标定）
7. **5-seed 全套**（每个 cell 至少 5 seed，审稿稳健基准），逐种独立记录
8. 产出：主表 MPC 行数据 + **求解失败证据图** + "MPC 需逐线重标定才有此性能"的立论量化（免重辨识成本的直接证据）
