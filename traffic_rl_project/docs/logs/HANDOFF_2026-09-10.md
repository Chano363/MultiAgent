## 0. 一分钟看懂：这是什么项目

**一句话**：用**人工智能（强化学习）+ 物理仿真**，研究"多列重载列车（装煤的大火车）在
长大下坡上怎么自动协同开，既不追尾、车钩不被拉断、又保持队形"。

- **研究对象**：一万吨级重载列车群组（1 台机车 + 100 节货车 = 一列；多列排成一队开）。
  真实背景：朔黄铁路（山西→河北运煤专线），有个 53 公里长的大下坡。
- **两阶段**：
  - 阶段一：无人机编队（**已完成的历史成果**，代码还在，别管它）。
  - 阶段二（**当前主战场，你的核心工作**）：重载列车群组协同控制。
- **三个关键物理名词**（后面会反复出现）：
  - **车钩力（coupler force）**：车钩是连着车厢的挂钩。力 >1000 kN 会把钩拉断。**底线，绝不可破**。
  - **长大下坡（long downhill）**：一整段大坡，重力自己就会让车加速，必须持续刹车。
  - **纵向冲动（jerk）**：刹车不当，前后车厢互相挤压/拉扯的冲击力。
- **三个英文代号**（D-RL = 分布式动力 + MAPPO 决策【主角】；D-Rule = 纯规则【基线】；MPC = 数学最优控制【基线】）：详表见 §10。

## 2. 项目要解决的科学问题（研究定位）

> 权威出处：`docs/RESEARCH_POSITIONING.md`（阶段二定位 + 创新点）。这里给你红色版本。

### 2.1 论文题目（最终目的）
> **面向长大下坡场景基于多智能体强化学习的重载列车群组自动控制方法**

### 2.2 一句话立论（SSOT，不可偏离）
> 多列编队（保持安全列距 + 速度带一致 + 车钩力≤1000kN）= **最终目的**；
> MARL（多智能体强化学习）= **手段**，不是目的。

### 2.3 核心创新点（答辩/审稿的卖点）
1. **显式建模车钩力**：现有长大下坡 RL 工作（Zhang2024、Liu2021、Wang2025）**全都忽略车钩力**；你项目把车钩力当硬约束，且作为观测上下文。
2. **多列群组协同**：从"单列"扩展到"多列编队"，是**物理必需**（后文会证明：没协同，多列长大下坡必然散架）。
3. **分层控制架构**（改架构，不是纯 RL 硬控）：
   ```
   编队目标（最终目的）: 多列群组长大下坡协同（列距/速度带/车钩力≤1000kN）
        ↓ 由同一套 RL 承载（编队上下文）
   RL 落位（唯一手段）: 每台机车=智能体，ED(电制动)/AB(空气制动) 分工
        ↓ 目标速度/档位
   底层执行（确定性）: 列内规则循环制动 + 车钩力安全层（强制 ≤1000kN）
   ```
   寓意：**RL 只负责"学怎么协同刹车"，底层规则控制器保证"物理安全绝对可靠"**，RL 乱来也破不了底线。

### 2.4 一个重要的"对比规范"Regime A/B（写论文时必须标）

> **【superseded（2026-09-16，ADR-016 覆盖 ADR-010/ADR-014 的 Regime B 部分）】**：本节 B 表述已废止——**MPC 对比只留 Regime A**（逐线重喂该线 `grade_at` 图纸 + 在线标定 b0，公平标定）；D-RL 跨线**严格零微调**（公开声明 "no fine-tuning on target line"）；核心 claim 由"Project 核心 claim 是 B（MPC 不重辨识→不行）"**改押"免重辨识成本"**：零重标定代价的 MARL ≈ 逐线重标定后的 MPC。权威：`docs/logs/decisions/DECISIONS.md` ADR-016 + `docs/RESEARCH_POSITIONING.md` §1.5/§1.6。以下原文保留，仅作历史。

- **MPC 对比**不按坡道换模型。
- **Regime A**（公平）：每线重喂坡道数据，MPC 有充足信息 → 公平对比。
- **Regime B**（免重辨识泛化证明）：不重辨识（no-reidentification），MPC 直接拿训练地模型去新线路 → 证明 MPC 不泛化。
- **Project 的核心 claim 是 B**：D-RL 免重辨识跨线守住底线，MPC 不行。

## 7. 踩坑史 / 上路前必看教训（极其重要，全列在这防你再踩）

> 详细版在 `AGENTS.md` Gotchas 和 `docs/logs/learnings/LEARNINGS.md`。这里是最要命的。

### 7.1 配置 & 工程坑
1. **YAML 不能写科学计数法**：`3e-4` 会被解析成字符串！写 `0.0003`。
2. **YAML 路径要跟代码 `.get()` 精确匹配**：不匹配会**静默回退默认值**（不报错），超参假生效。
3. **INFO 日志不打印**：脚本入口必须 `logging.basicConfig(level=logging.INFO)`。
4. **Loss 恒 0**：确保 `batch_size ≤ n_steps`，否则 buffer 永远不满。

### 7.2 物理/仿真坑（决定数据真不真）
5. **Davis 阻力被放大 w 倍（已修）**：空气阻力必须是标准形式 `0.0018·C·A·V²`（独立于车重），否则速度上限被低估到 8m/s。
6. **制动传播被 dt 吞掉（已修）**：空气制动传播延迟按**车辆累计长度/波速**算（几百米→数秒真实延迟），不要用车钩 free_length。
7. **Newmark 欠松弛污染（已修）**：收敛后必须取未松弛候选解，否则动力学整体缩水 25%。
8. **`ab_command=None` ≠ 缓解**：None 是不用空气制动，须单独分支处理，否则列车蠕动。
9. **静止起步牵引力泄漏（已修）**：`v<=1e-6` 时先判 `throttle<=0 → 0`。
10. **安全层修正动作 → 必须重算 log_prob**：否则策略不发散（V5.1 三层 bug 链）。

### 7.3 MAPPO 训练稳定性坑（当前正卡在这，重要）
11. **value_loss 爆炸 → 用 ValueNorm(PopArt)**：多智能体累计回报 ~1e4-1e5，不用归一化会崩。
12. **超长时程 on-policy 训练固有崩溃（2026-09-10 核心发现，详见 §8）**：
    单条 2500+ 步轨迹上 GAE advantage 信噪比崩 → value 污染不可回退 → 策略坍缩。
    试过 6 个杠杆全失败，需换"并行多环境"结构（§8）。

### 7.4 立论/规范坑
13. **训练/评估参数必须一致**（动作量化、缓解方式）否则仿真有 gap、结果误导。
14. **训练结论必须落 metadata**，不信任从代码注释抠数字。
15. **MPC 对比**：不重喂 grade_at 必须标 no-reidentification，否则当 strawman。
16. **历史资产引用前要确认建模版本**：缓解波/动力学版本不同，数值不可比。

## 8. 当前卡在哪 + 下一步精确指令（⚠️ 动起来的地方）

### 8.1 现状（2026-09-10，最新）

**核心问题**：53km 主训练 D-RL 无法稳定长时程收敛。症状 = 训练到 2500-3000 步档时，
`reward` 骤降到负几万、`peakCoupler` 破 1000kN、`viol` 爆几百上千，且不恢复。

**已彻底定位根因（不是 bug，是算法结构问题）**：
> **MAPPO（on-policy 算法）在 6 机车编队 × 2500+ 步单条长轨迹上，
> advantage/value 估计信噪比崩溃 → value 污染不可回退 → 策略坍缩。**
> 与起点、reward、curriculum、AB 门控等都无关（已逐一证明）。

**已失败存档的 6 个杠杆**（都留痕在 `DIAGNOSTICS_2026-09.md`）：
| # | 杠杆 | 结果 |
|---|---|---|
| 1 | 相对列距锚定奖励改造 | 只修好短-中时程，长时程仍破线 |
| 2 | 车钩力惩罚强化（违反 SSOT，已回滚） | 无效且清错失 |
| 3 | 回滚后又验证 | 无效（破线非 reward 量纲） |
| 4 | AB 源头门控 | 无效 |
| 5 | curriculum 退火（放缓步长增长） | 无效（崩点不移除） |
| 6 | **BC 热启动**（行为克隆自我规则基线） | **有效但不够**：崩点从 2000 步推迟到 2500+ 步，但没根治 |

**铁证**（来自 `outputs/diag_53km_bc/seed0/results/*.csv`）：
```
ep1-10 (1000步): 完美, viol全0
ep11-21 (1000→2000): 原崩点扛住了 (15548/863kN/0)  ← BC 真有效
ep22-31 (2000步): 零星破线
ep32-46 (2500+步): 彻底崩塌 (ep42:-49069/1579kN/1839viol)
```
结论：**BC 把崩点从 2000 推到 2500+，说明"随机探索踩暴力吸态"确是载体，但长轨迹 value 失稳没解决。**

### 8.2 正在尝试的方向（并行多环境，✅ 已完成代码改造，待验证）

**打破"单条长轨迹 on-policy"这个根因前提** —— 用 **n_env 并行多环境**：
- 每个 episode 跑 **n_env 条独立短轨迹**（不同初始速度提供样本多样性），同一 agent 共享 buffer，
  全部收集后**统一一次 update** → advantage 信噪比提高 n_env 倍，value 不被单条长轨迹绑架。
- **结构不变**（还是 MAPPO/CTDE，保住论文 claim）、物理无损、算法不换。

**代码已改好**（`src/trainer/train_runner.py` + `config_schema.py` 加了 `n_env`/`parallel_traj_len`）：
- 冒烟验证已通过：`n_env=4 × 300 步 × 不同初速` 2ep，reward +2999、peak 632kN、viol 0，无报错。
- 伪代码逻辑：外层 `for ep` + 内层 `for ei in range(n_env)` 跑不同初速轨迹，
  全部 `store_transition` 进共享 buffer，最后 `inter.end_episode()` 统一 `update()`。

## 10. 术语速查表（给零基础）

| 术语 | 是什么（人话） |
|---|---|
| **RL / 强化学习** | AI 靠"试错 + 奖励/惩罚"自学决策，不靠人工写规则 |
| **MARL / 多智能体强化学习** | 多个 AI 一起学，还要协同（互相配合刹车） |
| **MAPPO** | 一种多智能体 RL 算法（收敛最稳定的那个，本项目只用它跑主结果） |
| **参数/超参数** | 训练前设定的"旋钮"（学习率、批大小等），影响收敛 |
| **on-policy / off-policy** | on-policy 只用"当前策略采的数据"更新（自言自语）；off-policy 可复用历史数据 |
| **GAE / advantage** | 衡量"这一步比预期做得好还是差"的公式，驱动 RL 学习 |
| **value 函数 / critic** | 评判"当前状态有多好"的网络 |
| **policy 网络 / actor** | 决定"这步该做什么动作"的网络 |
| **limit / 速度带** | 允许的速度范围（40-80 km/h，长大下坡循环制动的目标区间） |
| **车钩力 coupler force** | 车厢之间挂钩的力，底线 ≤1000 kN |
| **ATP / 安全层** | 铁规矩保护层：超速/超车钩力/要追尾时强制干预，绝不失效 |
| **D-RL / D-Rule / MPC** | 三种控制方案：强化学习 / 写死规则 / 数学最优控制 |
| **ED / AB** | 电制动（连续，稳，无冲动） / 空气制动（离散档位，有波速传播，产生冲动） |
| **循环制动** | 长大下坡上"刹车→加速→再刹车"的反复，保持速度不掉下限 |
| **curriculum（课程学习）** | 训练时逐步加长"一集跑多久"，像课程从易到难 |
| **seed（种子）** | 固定随机数，让同一命令可复现；5 个种子=跑 5 次验证鲁棒性 |
| **53km 剖面** | 朔黄线完整真实纵断面，当前主训练坡段（替代旧 23.8km） |
| **metadata** | 每次训练自动存的"身份证"（命令/种子/超参/物理版本），保证可复现 |
