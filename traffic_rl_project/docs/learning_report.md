# 多智能体无人机编队控制——基于强化学习的学习报告

学习周期：2026年5月

---

## 一、研究背景与目标

### 1.1 研究动机

本研究以无人机编队控制作为强化学习（Reinforcement Learning, RL）的入门实践课题，旨在通过具体的连续控制任务系统性地掌握强化学习的基本流程、核心概念与工程实践方法。选择无人机编队控制作为切入点的理由如下：

- **物理仿真的真实性**：采用 gym-pybullet-drones 专业仿真平台，提供基于 PyBullet 物理引擎的刚体动力学与碰撞检测，使学习过程贴近实际控制问题；
- **可参照的基线**：多智能体强化学习领域已有成熟的开放代码与基准实现可供参考学习；
- **技术挑战的完整性**：任务涉及连续动作空间设计、密集奖励函数构建、多智能体协同策略学习及超参数调试等多个核心环节，有助于全面理解 RL 的工程实践。

### 1.2 研究目标

- **短期目标**：基于多智能体强化学习实现三架无人机的编队控制，使各无人机能够在保持目标高度（1.0 m）的同时维持规定的编队间距（5.0 m）；
- **长期目标**：将上述方法迁移至重载列车虚拟编队控制场景，探索 CTDE（Centralized Training with Decentralized Execution）范式在列车纵向动力学控制中的适用性。

## 二、强化学习理论基础

### 2.1 核心要素

强化学习的核心框架可概括为：智能体（Agent）在与环境（Environment）的交互过程中，通过最大化累积奖励学习最优策略。其四个核心要素定义如下：

- **状态（State, $s$）**：智能体在某一时刻感知到的环境信息。在本项目中，每架无人机的观测为 72 维，包含 12 维当前运动学状态（位置 $(x,y,z)$、欧拉角 $(r,p,y)$、线速度 $(v_x,v_y,v_z)$、角速度 $(\omega_x,\omega_y,\omega_z)$）以及 60 维历史动作缓存（过去 15 步的 4 维速度指令序列），用以补偿 PPO 类算法缺乏显式记忆机制的不足。
- **动作（Action, $a$）**：智能体可执行的决策指令。本项目的动作空间为 4 维连续速度指令 $[v_x, v_y, v_z, \text{mag}] \in [-1, 1]^4$，物理上限为 3 m/s，零指令对应悬停状态。
- **奖励（Reward, $r$）**：环境对智能体动作的即时反馈信号。奖励函数的设计直接决定了策略的学习方向与最终性能。
- **策略（Policy, $\pi$）**：从状态到动作的映射函数，是智能体的行为准则。在本项目中，策略由神经网络参数化表示。

### 2.2 数学基础

**折扣累积回报**（Discounted Cumulative Return）衡量智能体在时间步 $t$ 之后的长期收益：

$$G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots$$

其中折扣因子 $\gamma = 0.99$，表示越遥远的未来收益对当前决策的贡献权重越低。$\gamma = 0.99$ 意味着 10 步之后的奖励折算为当前价值的 $0.99^{10} \approx 0.9$ 倍。

**状态价值函数**（State-Value Function）评估从某一状态出发所能获得的期望累积回报：

$$V(s) = \mathbb{E}[G_t \mid s_t = s]$$

**优势函数**（Advantage Function）衡量在某一状态下采取特定动作相较于平均水平的优劣程度：

$$A(s, a) = Q(s, a) - V(s)$$

当 $A(s, a) > 0$ 时，表明该动作优于平均水平，策略应倾向于增加该动作被选中的概率。

### 2.3 多智能体强化学习（MARL）基础

多智能体强化学习的核心设定为：$k$ 个智能体在同一环境中同时学习，每个智能体基于局部观测 $o_i$ 独立决策 $a_i$，但所有智能体的联合动作 $\mathbf{a} = (a_1, \dots, a_k)$ 共同决定环境的状态转移与奖励分配。其关键特性包括：

| 概念 | 定义 |
|:---|:---|
| **智能体**（Agent） | 独立决策的个体，每个智能体拥有独立的策略网络 $\pi_i$ |
| **局部观测**（$o_i$） | 智能体可感知的部分环境信息，通常不等于全局状态 |
| **联合动作**（$\mathbf{a}$） | 所有智能体动作的集合 |
| **全局状态**（$s$） | 环境的完整描述，训练时可访问，执行时不可见 |
| **团队奖励**（$r$） | 所有智能体共享同一奖励信号，以促进协同行为 |
| **信用分配**（Credit Assignment） | 将团队总体表现归因到各智能体个体贡献的机制 |

与单智能体 RL 的关键区别在于：多智能体环境中，其他智能体的策略也在持续变化，导致状态转移函数呈现**非平稳性**（Non-stationarity），这是 MARL 的核心技术挑战之一。

本项目属于**完全合作**（Fully Cooperative）任务类别——三架无人机共享同一团队奖励信号，共同最大化编队控制效果。

### 2.4 算法架构：CTDE 范式

本项目采用**集中式训练与分布式执行**（Centralized Training with Decentralized Execution, CTDE）范式。该范式的核心思想为：

- **训练阶段**：Critic 网络接收全局状态（所有智能体的观测与动作）学习价值函数，Actor 网络仅接收局部观测输出动作。集中式价值函数能够有效缓解多智能体环境中的非平稳性问题。
- **执行阶段**：仅 Actor 网络参与推理，各智能体仅凭自身局部观测独立决策，无需通信，满足实际部署中的去中心化需求。

CTDE 在多种 MARL 算法中均有实现，包括 MAPPO、MADDPG、QMIX 等。本项目最终选用 MAPPO（Multi-Agent Proximal Policy Optimization）作为核心算法，其继承了 PPO 的截断机制以约束策略更新幅度，同时通过 CTDE 架构适配多智能体协同场景。

## 三、项目实现过程

### 3.1 仿真环境搭建

基于 gym-pybullet-drones 仿真平台中的 MultiHoverAviary 构建自定义 Gym 环境接口（包含 `reset`、`step`、`render` 等标准方法）。环境搭建过程中重点解决了以下问题：

- **动作空间的适配**：将原始 RPM（旋翼转速）动作空间替换为 VEL（速度指令）动作空间，降低策略学习的复杂度；
- **截断条件的调整**：原始仿真器的位置限制（`abs(x) > 2.0`）无法适配编队控制中无人机起始位置相距较远的设定，经分析源码后将其放宽至 `abs(x) > 20.0`，同时禁用了过于严苛的姿态角截断条件（roll/pitch > 1.5 rad），避免 aprendizaje 因姿态偶发激进而提前终止；
- **最大速度的约束**：将最大速度由 3.0 m/s 降至 1.0 m/s，限制探索阶段的动作幅度，提高训练的稳定性。

### 3.2 奖励函数设计

奖励函数的数学表达经四版迭代后确定为如下形式：

$$R = r_h + r_f + r_s + r_b$$

其中各分量的定义与权重分配如下：

- **高度惩罚项**：$r_h = -w_h |z - z_t|$，权重 $w_h = 1.0$，为最主要的目标项。当前高度 $z$ 偏离目标高度 $z_t = 1.0\ \text{m}$ 越远，惩罚幅度越大。
- **编队惩罚项**：$r_f = -w_f |d_{ij} - d_t|$，权重 $w_f = 0.5$。$d_{ij}$ 为相邻无人机间实际距离，$d_t = 5.0\ \text{m}$ 为目标间距。权重设为主目标的一半，以防止编队保持需求压制高度控制需求。
- **生存奖励项**：$r_s = +w_s$，权重 $w_s = 1.0$。每存活一步获得固定正值奖励，确保"不坠机"的基本收益与高度控制收益处于同一量级。
- **边界惩罚项**：$r_b = -w_b \cdot \mathbb{I}[\text{out of bound}]$。飞出安全区域时施加惩罚：$z > 8\ \text{m}$ 时罚 $-2.0$（高空坠毁风险），$z < 0.3\ \text{m}$ 时罚 $-0.4 \times (0.3 - z)$（擦地风险）。

奖励函数的设计经历了四次迭代，核心经验可归纳为：

1. **L1 范数惩罚优于 L2 范数**：L2 惩罚在大误差时梯度爆炸（误差 3-5 m 时平方项可达 9-25），在小误差时梯度消失（误差约 0.2 m 时平方项仅 0.04），造成训练不稳定。L1 惩罚提供恒定的梯度 $\pm 1$，在任何误差量级下均提供一致的优化信号。实验对比表明：L2 惩罚下最优奖励仅 $-10.70$ 且持续 230 轮无法改善，切换至 L1 惩罚后提升至 $+34.30$。
2. **熵系数的任务适配性**：高熵系数（0.008）导致策略持续输出随机速度指令，无人机持续漂移，最优策略（悬停保持编队）无法被有效探索。将熵系数由 0.008 逐步降低至 0.001 后，最优奖励由 $-10.70$ 提升至 $+34.30$，编队精度提升至约 0.076 m。
3. **权重分配的消融原则**：编队权重超过 1.0 将导致智能体为保持编队而牺牲高度控制；生存权重超过 2.0 将导致策略过于保守。最终权重 $(w_h, w_f, w_s) = (1.0, 0.5, 1.0)$ 在三个目标间取得了合理平衡。

### 3.3 算法选型与对比

以下三种算法在项目不同阶段、使用不同版本的奖励函数分别训练，其奖励值量级不可直接横向对比。此处仅记录调试观察，而非公平的算法基准测试。

| 算法 | 架构范式 | 训练轮次 | 奖励变化历程 | 观察结论 |
|:---|:---|:---:|:---|:---|
| PPO | 单智能体 | 6,415 | 前 99% 轮次奖励在 0 附近，末段约 70 轮跃升至 677 | 单智能体架构在编队协同任务中数据效率极低，需大量样本才能偶然发现有效策略 |
| SAC | 最大熵 | 1,864 | 早期飙至 6,751 峰值后持续退化至 $-353$ | 使用早期大权重奖励函数，训练不稳定，关闭自适应熵调节后仍有退化倾向 |
| MAPPO | CTDE | 500 | $-80 \sim +235$，快速收敛 | 收敛快、效果稳定，采用为最终方案 |

**PPO 的单智能体尝试**：将三架无人机的动作拼接为 12 维联合动作空间，采用标准 PPO 算法训练。训练过程中奖励长期处于 0 附近（每步仅能获取约 $-0.01$ 的微量信号），无人机基本未能习得有效的飞行控制策略。在训练末段约 70 轮中，奖励突然跃升至 100-677 区间。这一现象表明，在无法利用队友信息的条件下，单智能体 PPO 需要极大量的采样才能偶然发现有效策略，数据效率存在根本性局限。

**SAC 的最大熵尝试**：SAC 使用的奖励函数版本与最终版不同——早期版本的奖励权重更大，单步奖励可达 6-10，因此观测到的 2,700-6,751 的奖励值仅为量级差异，不代表实际控制效果更优。SAC 的策略在训练中期（约第 50 轮）达到峰值后持续退化，最终降至 $-353$。关闭自适应熵调节（adaptive alpha）后退化有所缓解，但整体仍不稳定。

**MAPPO 的最终方案**：MAPPO 采用 CTDE 架构——各智能体独立决策，但训练时利用全局状态学习集中式价值函数。这一设计天然适配编队协同场景：共享策略网络使所有智能体学习同一套参数，而集中式价值函数有效缓解了多智能体环境中的非平稳性问题。MAPPO 在 500 轮内快速收敛，奖励稳定在 $+100 \sim +150$ 区间。

### 3.4 超参数调试

超参数调试是项目过程中耗时最长的环节。以下总结关键参数的调试经验：

| 参数 | 尝试范围 | 最终取值 | 调试发现 |
|:---|:---:|:---:|:---|
| 学习率（Learning Rate） | $3 \times 10^{-4} \sim 5 \times 10^{-5}$ | $5 \times 10^{-5}$ | 过大导致策略在多智能体非平稳环境中振荡崩溃 |
| 熵系数（Entropy Coefficient） | $0.001 \sim 0.008$ | $0.005$ | 过低导致策略过早收敛至局部最优，过高则稀释有效策略 |
| KL 散度早停阈值 | 初始未使用 | $0.01$ | 防止策略更新幅度过大导致训练崩溃 |
| 训练轮次（Epochs） | $4 \sim 10$ | $4$ | 过多轮次导致策略过拟合单批数据，产生振荡 |
| 批次大小（Batch Size） | $64 \sim 128$ | $64$ | 必须不超过单 episode 步数，否则缓冲区无法填满导致更新不被触发 |

关键发现总结如下：

- **学习率的敏感性**：MAPPO 的多智能体架构对学习率的要求较单智能体 PPO 更为严格。$3 \times 10^{-4}$ 的学习率导致策略在"各智能体相互适应"的过程中持续振荡；降为 $5 \times 10^{-5}$ 后实现稳定收敛。
- **Batch Size 的约束条件**：Batch size 必须不大于单 episode 的步数上限，否则经验回放缓冲区无法累积足够的样本触发策略更新，造成模型从未更新的"静默失败"——损失函数持续为零而训练者不易察觉。
- **KL 散度早停的防护作用**：当一次 epoch 更新后策略变化过大（KL 散度超过 0.01 阈值）时，该轮更新将被终止。这一机制相当于训练过程的"保险丝"——在策略即将失控时及时介入，防止更新幅度过大导致的性能崩塌。

### 3.5 工程实践教训

**动作空间维度的一致性**：在多智能体 PPO 实现中，算法期望的动作维度为展平（flatten）后的联合动作维度（12 维 = 3 架无人机 × 4 维），而环境交互时需使用重塑（reshape）后的矩阵形式（形状 $[3, 4]$）。训练过程中若存储的 transition 数据维度与算法期望不匹配，将引发维度错误，导致训练流程中断。

**配置文件的数值表示**：YAML 配置文件中的科学计数法表示（如 `3e-4`）可能被解析器误读为字符串而非浮点数，导致参数退回默认值而不产生任何错误提示。因此，配置文件中应始终使用十进制小数表示（如 `0.0003`）。

**防御性参数验证**：训练流程启动时应打印所有关键超参数的实际取值，并对参数间的合理性进行验证。例如，当 `batch_size > n_steps` 时应发出明确警告，提示缓冲区可能无法触达触发更新的阈值。

## 四、训练结果与分析

### 4.1 训练阶段划分

MAPPO 使用最终版奖励函数训练 500 轮，训练过程大致分为四个阶段：

1. **探索阶段（第 1-50 轮）**：奖励在 $-80$ 至 $+100$ 之间大幅波动，智能体处于随机试错阶段；
2. **学习阶段（第 51-150 轮）**：奖励稳步上升，智能体开始习得维持目标高度 $1.0\ \text{m}$ 的基本能力；
3. **提升阶段（第 151-300 轮）**：编队误差明显下降，智能体开始协调各机之间的位置关系以保持队形；
4. **收敛阶段（第 301-500 轮）**：奖励稳定在 $+100 \sim +150$ 区间，编队与高度控制指标趋于稳态。

### 4.2 最终性能指标

| 指标 | 训练目标 | 最终结果 |
|:---:|:---|:---:|
| **总奖励** | 最大化至收敛稳定 | $150 \pm 30$ |
| **高度误差** | $< 1.0\ \text{m}$（目标高度 1 m） | $0.38\ \text{m} \pm 0.10\ \text{m}$ |
| **编队误差** | $< 0.75\ \text{m}$（目标间距 5 m，偏差 15%） | $0.50\ \text{m} \pm 0.15\ \text{m}$ |
| **生存步数** | $400/400$（满步数不坠机） | $400/400$ |

说明：

- **高度误差**的计算方式为：每步对三架无人机的实际高度与目标高度（1.0 m）之差的绝对值取平均，再对收敛阶段（最后约 150 轮）的所有 episode 取均值，得到 $0.38\ \text{m}$。
- **编队误差**的计算方式类似：每步对相邻无人机间的实际距离与目标间距（5.0 m）之差的绝对值取平均，收敛阶段均值为 $0.50\ \text{m}$。
- 以上指标反映了 CTDE 架构在协同控制任务中的有效性——三架无人机能够在共享奖励信号的引导下，同时满足高度保持与编队保持的双重目标。

### 4.3 推理模式对比

训练过程中采用随机采样（Stochastic）模式——动作从策略网络输出的分布中采样，以维持探索能力。测试/推理时采用确定性（Deterministic）模式——直接使用策略网络输出的均值作为动作指令。两种模式的对比结果如下：

| 推理模式 | 平均奖励 | 标准差 |
|:---|:---:|:---:|
| 随机采样 | 93.4 | ±37.0 |
| 确定性推理 | 115.3 | ±15.3 |

确定性推理在均值与方差两方面均优于随机采样，表明策略网络学习到的动作均值本身已具备良好的控制性能，采样引入的随机性在测试阶段反而增加了控制的不确定性。

## 五、核心经验总结

### 5.1 技术层面

1. **奖励函数设计是强化学习项目的核心瓶颈**。强化学习的基本假设是"智能体可通过最大化累积奖励习得最优策略"，若奖励函数设计存在缺陷，再强的算法也无法产出有效的策略。本项目中，奖励函数的迭代占据了约 60% 的调试时间。
2. **L1 范数在连续控制中优于 L2 范数**。L2 惩罚在大误差时梯度爆炸、小误差时梯度消失，L1 惩罚提供恒定梯度，在各误差量级下均保持一致的优化信号，有利于训练的稳定收敛。
3. **CTDE 范式对多智能体协同任务具有显著优势**。相比于单智能体 PPO 需要将联合动作拼接为高维空间进行学习，MAPPO 的 CTDE 架构允许各智能体独立决策的同时利用全局状态信息学习价值函数，有效缓解了多智能体环境中的非平稳性问题，在数据效率方面实现了数量级的提升（PPO 需 6,415 轮，MAPPO 仅需 500 轮）。
4. **超参数对 RL 训练的影响远超监督学习**。尤其是学习率与熵系数，其微小变动即可导致训练从"稳定收敛"变为"完全崩溃"。

### 5.2 方法论层面

1. **系统化的调试流程**：启动训练后首先检查动作值范围是否合理、episode 终止原因（正常结束或异常截断）、缓冲区采样数量是否足以触发策略更新、损失函数是否非零等，可快速定位大部分常见问题。
2. **控制变量法的实验管理**：每次仅修改一个参数，便于精准定位问题来源；对每次实验的关键指标进行记录，避免重复试错。
3. **理解底层源码的必要性**：gym-pybullet-drones 等开源仿真器的源码包含大量与 RL 训练直接相关的底层逻辑（截断条件、状态表示、动作映射等），阅读源码是解决仿真环境相关问题的可靠途径。

## 六、存在的不足

1. **高度控制精度不足**：0.38 m 的误差相对于 1.0 m 的目标高度偏差 38%，仍有优化空间，预期经过更精细的奖励函数调整后可降至 0.2 m 以内。
2. **任务场景相对简化**：当前仅实现了三架无人机的静态编队保持，未涉及障碍物规避、编队重构等更具挑战性的场景。
3. **仅在仿真环境中验证**：策略尚未经实物平台验证，Sim-to-Real 迁移的有效性有待检验。
4. **超参数调试依赖经验**：当前超参数搜索主要依靠手动试错与直觉判断，缺乏系统化的超参数优化（HPO）方法支持。
5. **训练流程效率可优化**：当前训练速度受限于环境步进效率，可引入 PufferLib 等高性能向量化框架实现加速。

## 七、后续工作：面向重载列车编队的迁移

### 7.1 迁移动机

本项目的长期目标是将无人机编队控制中习得的方法迁移至重载列车虚拟编队控制。重载列车（通常由 3-6 节车厢组成）在铁路货运中扮演核心角色，其编队控制的核心问题包括：

- 多节车厢间的纵向耦合控制（保持安全间距、抑制车钩冲击）；
- 复杂线路条件下的协同制动与牵引；
- 纵向冲动控制（车厢间的压缩/拉伸力）对运行安全的保障。

### 7.2 经验的可迁移性

| 无人机项目经验 | 列车编队中的对应迁移 |
|:---|:---|
| 状态空间设计 | 列车状态：位置、速度、车钩力、制动缸压力、线路坡度等 |
| 动作空间设计 | 牵引/制动指令（分级或连续） |
| 奖励函数设计 | 纵向冲动最小化 + 间距保持 + 能耗优化 |
| CTDE 架构 | 各车厢独立编队决策，全局状态训练价值函数 |
| KL 早停机制 | 防止策略更新过大导致列车控制振荡 |
| 确定性推理 | 推理时采用均值输出，保证控制稳定可预测 |

### 7.3 仿真器调研与选择

经调研，选定 NeTrainSim（Network Train Simulator）作为列车动力学建模的参考来源。NeTrainSim 由弗吉尼亚理工大学交通运输研究所开发（GPLv3 开源），专为货运列车纵向动力学设计，建模了牵引力、制动力、滚动阻力、坡度阻力与车钩力等关键物理量，具有学术论文支撑，动力学模型可信度高。

实现路径为：从 NeTrainSim 的论文及源代码中提取列车纵向动力学建模公式，使用 Python 与 NumPy 实现后封装为标准的 Gym 环境接口。

### 7.4 相关工作

近年来的研究表明，MAPPO 已被成功应用于重载列车群组协同控制。Song、Li、Wang 与 Yang（2026）在《Cooperative Control for Heavy-Haul Train Groups Based on Multi-Agent Reinforcement Learning》中，以 MAPPO 为算法框架实现列车群的速度同步与间距保持控制，验证了 CTDE 架构在列车编队场景中的可行性。该工作与本项目的技术路线高度一致，进一步确认了迁移策略的合理性。

此外，虚拟编组（Virtual Coupling）作为列车版的"编队控制"概念，近年来已成为铁路领域的研究热点，Liu 等（2025, IEEE ITS Magazine）已采用 MARL（DQN）实现虚拟编组列车的协同运行策略。

### 7.5 下一步工作计划

1. **仿真环境搭建**：基于 NeTrainSim 提取列车纵向动力学模型，封装为 Python Gym 环境；
2. **算法迁移**：将 MAPPO 的 CTDE 架构迁移至列车编队，设计适配列车特性的奖励函数（纵向冲动最小化、间距保持、能耗优化）；
3. **对比分析**：系统比较无人机编队与列车编队在动作空间、时序特性、安全约束等方面的差异，并据此调整算法设计。
