## 二、强化学习基础概念——我是怎么理解的

### 2.1 核心四要素

```
智能体（Agent）←——奖励——→ 环境（Environment）
     ↓ 动作
     ↓
  状态更新
```

- **状态（State）**：无人机在某一时刻的所有信息——位置在哪、飞多快、姿态怎样。我这里的每架无人机有72维状态。
- **动作（Action）**：智能体做出的决策。我的项目里是4个参数：三个方向的速度 + 一个速度大小。
- **奖励（Reward）**：环境告诉智能体"你做得好不好"。我的奖励函数包含：飞得高不高、离队友远不远、有没有出界。
- **策略（Policy）**：智能体根据状态决定动作的规则。我的策略是一个神经网络，输入状态输出动作。

### 2.2 训练循环是怎样的

```
for episode in range(500):
    初始化环境，获得初始状态
    for step in range(400):           # 每轮最多走400步
        智能体根据当前状态选择动作
        环境执行动作，返回（新状态, 奖励, 是否结束）
        存储经验（状态、动作、奖励、新状态）
        智能体学习，更新策略
    输出本轮的总奖励
```

### 2.3 我学到的关键公式

**折扣累积奖励**——未来很重要但打折扣：

$$G_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \cdots$$

$\gamma=0.99$ 意味着10步后的奖励只值当前的 $0.99^{10} \approx 0.9$ 倍。

**价值函数**——告诉我这个状态值多少：

$$V(s) = \mathbb{E}[G_t | s_t = s]$$

我理解为："在这个状态下，平均来说未来能拿多少奖励"。

**优势函数**——告诉我这个动作好不好：

$$A(s,a) = Q(s,a) - V(s)$$

正值意味着"这个动作比平均水平的价值高"。

### 3.2 奖励函数设计（这是最核心的部分，没有之一）

**为什么奖励函数是核心？**

强化学习的核心假设是：**智能体可以通过最大化累积奖励来学习到最优策略**。如果奖励函数设计得不好，不管算法有多强，最终策略肯定有问题。这就像给人考试出题，如果题目出得错了，分数再高也说明不了什么。

#### 设计原则（我学到的学术规范）

好的奖励函数应该遵循以下原则：

1. **明确性**：奖励应该明确反映任务目标，不要让智能体猜测什么是对的
2. **稀疏性vs密集性**：需要平衡——太稀疏学不会，太密集又容易过拟合到局部奖励
3. **可导性**：最好是连续可微的，便于梯度下降
4. **归一化**：各项奖励的量级要匹配，避免某一项完全主导训练
5. **可解释性**：能通过调整权重方便地控制各目标的优先级

#### 迭代历程（从debug文档中整理的真实迭代）

奖励函数不是一步到位的，前后经历了**4个版本的迭代**才达到最终版本：

---

**版本1.0：L2（二次）惩罚**

```python
reward -= 0.05 * dist_error ** 2   # 距离误差平方
reward -= 0.03 * alt_error ** 2    # 高度误差平方
reward += 0.15                     # 每步生存奖励
```

**问题**：
- 大误差时梯度爆炸：随机探索时无人机漂移3-5m，误差²=9-25，单步惩罚可达1.25
- 小误差时梯度消失：策略接近最优时误差~0.2m，误差²=0.04，惩罚仅0.002，策略感知不到进一步优化的信号
- **Best Reward卡在-10.70，230轮无改善**

---

**版本2.0：改用L1（线性）惩罚**

```python
reward -= 0.05 * abs(dist_error)   # 线性惩罚，梯度恒定
reward -= 0.02 * abs(alt_error)
reward += 0.15                     # 生存奖励不变
```

**效果对比**：

| 指标 | L2惩罚（ep260） | L1惩罚（ep530） |
|:---|:---|:---|
| Best Reward | -10.70（无法突破零） | **+34.30** |
| 收敛速度 | 230轮无改善 | 30轮达到正收益 |
| 编队精度 | ~1.1m | **~0.076m（8cm）** |

**结论**：L1惩罚提供恒定梯度，不论误差大小都给出相同的优化信号，解决了L2的梯度爆炸/消失问题。

---

**版本3.0：调整熵系数**

最初使用 `entropy_coef: 0.008` 鼓励探索，但发现：
- 高熵 → 策略持续输出随机速度指令 → 无人机不断漂移
- 最优策略（输出零速度保持初始编队）无法在高熵下被发现

| 阶段 | entropy_coef | Best Reward |
|:---|:---|:---|
| 初始 | 0.008 | -10.70，无法收敛 |
| 优化1 | 0.003 | +5.94，收敛到~1m精度 |
| 优化2 | **0.001** | **+34.30**，收敛到~8cm精度 |

**结论**：如果最优策略是"保持不动"（输出零速度），熵应该接近零。任何非零熵都会被奖励函数惩罚。

---

**版本4.0（最终版）：密集连续奖励+权重优化**

```python
r_h = -w_h * |z - z_target|  # 高度误差惩罚
r_f = -w_f * |d_ij - d_target|  # 编队距离误差惩罚
r_s = w_s  # 生存奖励
r_b = -w_b * [|x|>X_max || |y|>Y_max]  # 边界惩罚
R = r_h + r_f + r_s + r_b
```

**最终奖励函数组成：**

```python
total_reward = (
    -height_error * 1.0      # w_h = 1.0 （主目标）
    -formation_error * 0.5   # w_f = 0.5 （次目标，权重较低避免喧宾夺主）
    + 1.0                    # w_s = 1.0 （生存奖励，保证不坠机的收益与高度误差在同一量级）
    - boundary_penalty        # w_b 视情况而定（出界是硬约束，用较大惩罚）
)
```

#### 奖励项权重分配详解

| 奖励项 | 权重 | 设计考虑 |
|:---|:---|:---|
| 高度保持 | 1.0 | **主目标**，权重最大，引导智能体优先学习高度控制 |
| 编队保持 | 0.5 | **次目标**，权重较低，避免编队需求压制高度需求 |
| 生存奖励 | 1.0 | **安全约束**，保证"不坠机"的收益与"高度控制"在同一量级 |
| 边界惩罚 | 可调 | **硬约束**，出界是不可接受的，惩罚要足够大 |

**权重分配的实验依据**：

- 编队权重过高（>1.0）：智能体为了保持编队牺牲高度，导致高度控制失败
- 生存权重过高（>2.0）：智能体学会"尽量少动"以避免出界，策略过于保守
- 最终权重（1.0, 0.5, 1.0）在三个目标间达到了较好的平衡

#### 奖励函数设计经验总结

1. **先设计稀疏奖励，再逐步塑造**：先用稀疏奖励验证问题定义，再用密集奖励提高学习效率
2. **L1惩罚优于L2惩罚**：L1提供恒定梯度，L2在大误差时梯度爆炸、小误差时梯度消失
3. **熵系数要配合任务特性**：如果最优策略是确定性的，熵应接近零
4. **权重分配要做消融实验**：每次只改一个权重，观察对策略的影响
5. **不要试图一步到位**：奖励函数通常需要迭代几次才能达到好的效果
6. **如果智能体行为怪异，首先查奖励**：RL中80%的问题都可以通过调整奖励函数解决

#### 对重载列车编队的启示

无人机的奖励函数设计经验可以直接迁移到重载列车编队：

| 无人机奖励项 | 列车对应项 | 说明 |
|:---|:---|:---|
| 高度保持 | 车钩力控制 | 主目标（纵向冲动是重载列车的核心安全指标） |
| 编队保持 | 车距控制 | 次目标（安全间距） |
| 生存奖励 | 存活奖励 | 保证列车不脱轨 |
| 边界惩罚 | 信号约束 | 硬约束（红灯停车） |

此外，重载列车可能还要加入**能耗优化**项，需要设计多目标的权重分配策略。

### 3.3 算法选择（交了不少学费）

| 算法 | 我遇到的问题 | 结果 |
|:---|:---|:---|
| SAC | 高度控制一直很差，策略在后期退化 | ❌ 放弃 |
| PPO | 训练了6000多轮，奖励一直在0附近，无人机根本不会飞 | ❌ 放弃 |
| MAPPO | 500轮就收敛了，效果稳定 | ✅ 采用 |

**为什么PPO不行？（单智能体架构的局限性）**

单智能体PPO是给每个无人机独立训练的，但编队控制需要知道"队友在哪"。比如无人机A要飞向队友B的方向，但如果A看不到B的状态，就没法协调。

我还遇到了PPO实现上的问题：PPO的update()期望动作是flatten后的维度，但我在存储transition时存的是reshape后的形状，导致维度不匹配。这个bug让我花了很久才定位到。

MAPPO的改进是：每个无人机还是独立决策，但训练时用全局状态来学价值函数。这样"各跑各的"但"一起学"。

**为什么SAC退化了？**

SAC的自动熵调节（adaptive alpha）会把探索参数调大，结果后期策略变得太随机，本来学会的东西又忘了。改成固定小alpha后解决了。

**关于MAPPO我还学到了什么：**

- 集中式训练+分布式执行（CTDE）范式是多智能体RL的核心
- 共享策略网络让所有智能体学同一套参数，但每个智能体根据自己的观测独立决策
- 集中式价值网络需要全局状态作为输入，这是"集中式训练"的含义

### 3.4 超参数调试经验（这是最让我体会到"RL是玄学"的地方）

**为什么单独讲这个？**

因为这是我在整个项目中最宝贵的经验。调参占据了整个项目的大部分时间，而网上的教程往往只告诉你"用什么值"，不告诉你"为什么"和"怎么调"。

#### 调试方法论（我是怎么调的）

调参不是乱试，要系统化。我的调试流程是：

```
启动训练 → 检查第1个episode的:
  1. 动作值范围是否合理（不应爆表）
  2. episode终止原因（是正常结束还是被截断）
  3. buffer步数 vs batch_size（batch_size必须≤单episode步数）
  4. 前几个episode的Loss是否为非零（Loss=0说明模型从未更新）
```

#### 关键发现1：batch_size不是越大越好

一开始我把batch_size设成128，想让每次更新更稳定。结果发现Loss始终为0，模型根本没更新！

原因是：每个episode只有几十步，buffer永远填不满128步，update()根本不会被触发。

教训：**batch_size必须≤单episode步数**，否则buffer永远填不满。

#### 关键发现2：学习率对MAPPO异常敏感

| 学习率 | 结果 |
|:---|:---|
| 3×10⁻⁴ | 策略频繁崩溃，训练不稳定 |
| 5×10⁻⁵ | 稳定收敛，500轮达到最优 |

MAPPO的多智能体架构对学习率的要求比单智能体PPO更严格。原因可能是：多智能体环境中策略更新的非平稳性问题更严重，大学习率会导致策略在"各智能体相互适应"的过程中振荡。

#### 关键发现3：熵系数低了会策略坍缩，高了会探索不足

| 熵系数 | 结果 |
|:---|:---|
| 0.001（太低） | 策略过早收敛到局部最优，后期退化 |
| 0.005（适中） | 保持适度探索，最终收敛到好策略 |

熵系数控制随机性：太低→策略太确定→探索不足；太高→策略太随机→学到的有用技能被稀释。

#### 关键发现4：KL散度早停是"保险丝"

我在训练过程中遇到过一次策略突然崩溃（奖励从100+掉到0），排查发现是策略更新幅度过大导致的。

修复方法是加KL散度早停：如果一次epoch更新后策略变化太大（KL散度>0.01），就停止这轮更新。这相当于给训练过程加了一个"保险丝"，防止策略更新失控。

#### 关键发现5：训练轮次epochs越少越稳定

| epochs | 结果 |
|:---|:---|
| 10 | 策略振荡，奖励波动大 |
| 4 | 稳定收敛 |

每批数据训练次数越多，策略越容易过拟合到这批数据上，导致振荡。

#### 调参总结表

| 参数 | 我试的值 | 最终用的 | 教训 |
|:---|:---|:---|:---|
| 学习率 | 3e-4 → 太小没用 | 5e-5 | 太大学习不稳定，MAPPO敏感 |
| 熵系数 | 0.001 → 策略坍缩 | 0.005 | 太低探索不足，太高稀释技能 |
| KL早停阈值 | 一开始没有 | 0.01 | 防止策略更新失控的保险丝 |
| 训练轮次epochs | 10 → 策略振荡 | 4 | 越少越稳定，越多越容易过拟合 |
| batch_size | 128 → Loss=0不更新 | 64 | 必须≤单episode步数 |

### 3.5 具体的Bug修复经验（debug文档精华提炼）

这一节记录了我在实际调试过程中遇到的具体问题及其修复方法，是从debug文档中提炼出的最重要的经验。

#### Bug 2: PPO动作形状不匹配

**问题现象**：`update()`方法抛出`ValueError`：期望动作维度为12（flatten），实际为4（单个无人机动作维度）。

**根因分析**：训练脚本在存储transition时，存储的是reshape后的动作（形状`[3, 4]`），而PPO算法期望的是flatten后的动作（形状`[12]`）。

**修复代码**：
```python
original_action = action.copy()  # 保存原始flatten动作

if len(env.action_space.shape) == 2:
    action = action.reshape(env.num_drones, env.action_space.shape[1])
else:
    action = action.reshape(env.num_drones, 4)

# 传递给环境的是reshape动作
rpm_action = HOVER_RPM * (1 + 0.05 * action)
next_state, reward, terminated, truncated, info = env.step(rpm_action)

# 存储的是原始flatten动作
agent.store_transition(flattened_state, original_action, reward, log_prob, done, value)
```

**预防措施**：在PPO的`update()`方法中添加动作形状断言：
```python
if len(actions.shape) > 2:
    raise ValueError(f"动作形状错误！期望形状 [batch_size, {expected_action_dim}]，实际形状 {actions.shape}。")
```

#### Bug 4: Episode在第1步后立即终止

**问题现象**：每个episode在第1步就被截断（truncated=True），无法进行有效训练。

**根因分析**：`MultiHoverAviary._computeTruncated()`中的位置限制条件过于严格（`abs(x) > 2.0`），而编队控制环境中无人机的起始位置距离较远（x=5.0, x=10.0），远超2.0米限制。

**修复方法**：放宽位置限制：
```python
# 修复前
if (abs(states[i][0]) > 2.0 or abs(states[i][1]) > 2.0 ...

# 修复后
if (abs(states[i][0]) > 20.0 or abs(states[i][1]) > 20.0 ...
```

#### Bug 6: VEL动作空间+PID控制的不稳定性

**问题现象**：切换到VEL动作空间后，85%的episode在30-60步内被提前截断，导致buffer大小始终小于batch_size，Loss持续为0。

**根因分析**：MultiHoverAviary的`_computeTruncated()`设置了`roll/pitch > 1.5rad`（约86°）的截断条件。在VEL动作空间中，PPO的随机动作输出[-1, 1]经PID解算后产生激进的姿态变化，roll频繁达到3+ rad。

**诊断方法**：
```python
if truncated and self.steps < self.max_steps - 10:
    states = np.array([self.aviary._getDroneStateVector(i) for i in range(self.num_drones)])
    reasons = []
    for i in range(self.num_drones):
        if abs(states[i][7]) > 1.5:
            reasons.append(f"Drone{i}:roll={abs(states[i][7]):.2f}>1.5")
    if reasons:
        logging.warning(f"提前截断 @ step {self.steps}: {'; '.join(reasons)}")
```

**修复方法**：
| 修改 | 变更 |
|------|------|
| 倾斜截断禁用 | `abs(roll) > 1.5` → `abs(roll) > 10.0` |
| 降低最大速度 | `max_speed: 3.0` → `max_speed: 1.0` |

### 3.6 YAML类型陷阱与防御性参数验证

#### YAML类型陷阱


**教训**：在YAML中始终使用十进制小数而非科学计数法表示浮点数。

#### 防御性参数验证

建议在Agent的`__init__()`中添加参数验证和日志输出：
```python
def __init__(self, ..., batch_size, n_steps, ...):
    # 打印实际使用的参数
    logger.info(f"PPO 参数: batch_size={batch_size}, n_steps={n_steps}, "
                f"lr={learning_rate}, gamma={gamma}, ...")
    
    # 验证参数合理性
    if batch_size > n_steps:
        logger.warning(f"batch_size({batch_size}) > n_steps({n_steps}), "
                       f"每个 episode 可能无法触发 update")
```

## 四、训练结果

### 4.1 训练指标设计

训练日志输出格式：
```
Episode  100/1000 | Reward: +235.50 | Avg10:  220.30±15.20 | Best:  235.50 | Loss: -43.9218 | Speed:  1.08 m/s | FormationErr: 0.500 m | HeightErr: 0.380 m
```

| 指标 | 含义 | 目标/说明 |
|:---|:---|:---|
| **Reward** | 本轮总奖励 | 越高越好，理论上限约+420（+1.05/步×400步） |
| **Avg10** | 最近10轮平均奖励 | 观察收敛趋势，波动小说明训练稳定 |
| **Best** | 历史最优奖励 | 训练过程中达到的最高奖励 |
| **Loss** | 损失函数值 | PPO的policy loss + value loss，应为负值且逐渐减小 |
| **Speed** | 本轮平均速度 | 无人机运动速度，0.5-1.5 m/s为正常范围 |
| **FormationErr** | 编队误差 | 相邻无人机间距与目标5.0m的平均偏差，越接近0越好 |
| **HeightErr** | 高度误差 | 无人机高度与目标1.0m的平均偏差，越接近0越好 |

### 4.2 最终性能（MAPPO，500轮）

| 指标 | 数值 | 说明 |
|:---|:---|:---|
| 最优奖励 | 235.5 | ep430时取得 |
| 平均奖励 | 99.4 | 训练后期稳定在100左右 |
| 高度误差 | 0.38m | 目标高度1m，偏差38% |
| 编队误差 | 0.50m | 目标间距5m，偏差10% |
| 推理标准差 | ±15.3 | 确定性推理模式下很稳定 |

### 4.2 训练曲线解读

训练过程大致分为四个阶段：

1. **探索期（ep 1-50）**：奖励忽高忽低（-80到+100），智能体在随机试错
2. **学习期（ep 51-150）**：奖励稳步上升，智能体开始学会维持高度
3. **提升期（ep 151-300）**：编队误差明显下降，智能体开始协调位置关系
4. **收敛期（ep 301-500）**：奖励稳定在100-150，偶尔有小的波动

### 4.3 确定性推理的好处

训练时用随机采样（加了噪声），测试时用确定性（直接用神经网络输出的均值）：

| 模式 | 平均奖励 | 波动（标准差） |
|:---|:---|:---|
| 随机采样 | 93.4 | ±37.0 |
| 确定性推理 | 115.3 | ±15.3 |

确定性推理让控制更稳定，这对我来说是新发现——原来训练和测试可以用不同的动作选择方式。

## 五、我从这个项目学到的东西

### 5.1 技术层面

1. **强化学习不是拿来就能用**：动作空间、奖励函数、算法选择都需要针对问题设计
2. **连续奖励优于稀疏奖励**：提供平滑的梯度信号比偶尔给个大奖励更有效
3. **多智能体RL和单智能体RL很不一样**：MAPPO的成功说明"集中式训练+分布式执行"（CTDE）这个范式很关键
4. **超参数敏感**：RL对超参数非常敏感，需要耐心调试

### 5.2 调试方法层面

1. **看训练曲线**：如果奖励一直不涨或者突然崩塌，一定是哪里有问题
2. **看代码底层**：gym-pybullet-drones是开源的，看懂源码解决了我很多困惑
3. **控制变量法**：每次只改一个参数，便于定位问题
4. **记录实验**：实验多了以后发现之前的某些"灵机一动"其实是错的

### 5.3 对强化学习的理解

之前觉得RL就是"试错+奖励"，现在理解了这背后有一套严谨的理论：

- **探索与利用的权衡**：既要尝试新动作（探索），又要用已知的好策略（利用）
- **时序信用分配**：一个动作的后果可能在很久以后才显现，如何把荣誉/责任归因到正确的动作上是核心问题
- **泛化能力**：在仿真器里学会的策略能否迁移到真实环境，这是RL至今没有完全解决的问题

## 七、从无人机到重载列车——我的最终目标

### 7.1 为什么最终要做重载列车编队

无人机编队控制是我学习强化学习的**练手项目**，而不是最终目标。我的毕设/研究方向是**重载列车编队控制**。

重载列车（通常由3-6节车厢组成，总重可达万吨）在铁路货运中扮演着核心角色，其编队控制的核心问题是：
- 多节车厢之间的**纵向耦合控制**（保持安全间距、抑制车钩冲击）
- 复杂线路条件下的**协同制动与牵引**
- 纵向冲动控制（车厢间的压缩/拉伸力）对安全的影响

这个问题的难度远超无人机编队：列车的动力学特性更加复杂（大惯性、时滞、非线性摩擦），且一旦失控后果严重（重载列车的制动距离可达千米）。

### 7.2 无人机项目学到的东西如何迁移到列车

| 学到的内容 | 在列车编队中的对应/迁移 |
|:---|:---|
| 状态空间设计 | 列车状态：位置、速度、车钩力、制动缸压力、线路坡度等 |
| 动作空间设计 | 牵引/制动指令（分级或连续） |
| 奖励函数设计 | 纵向冲动最小化 + 间距保持 + 能耗优化 |
| CTDE架构 | 集中式训练（用全局状态学价值）+ 分布式执行（各车厢独立决策） |
| KL早停机制 | 防止策略更新过大导致列车控制振荡 |
| 确定性推理 | 推理时用均值输出，保证控制稳定可预测 |

### 7.3 还需要补充的知识

目前无人机项目的知识还不能直接用于列车控制，还需学习：

1. **列车空气制动系统原理**：制动波传播、充排风时间、制动缸压力与闸瓦力的关系
2. **车钩缓冲特性**：列车的纵向动力学模型（质量-弹簧-阻尼系统）
3. **线路参数建模**：坡度、曲线、隧道对阻力的影响
4. **安全约束**：铁路信号系统、追踪间隔、紧急制动距离
5. **数据来源**：与无人机不同，列车数据可能来自真实运营记录或专业仿真软件（如RailML）

### 7.4 仿真器调研结果

为了寻找可用的重载列车仿真环境，调研了现有的列车仿真器：

#### 推荐方案：NeTrainSim

| 项目 | 说明 |
|:---|:---|
| **名称** | NeTrainSim (Network Train Simulator) |
| **开发者** | 弗吉尼亚理工大学（Virginia Tech）交通运输研究所 |

- 支持多列车在网络级轨道上交互仿真，直接适用于编队场景

**Open Rails** ([openrails.org](https://www.openrails.org/)) — GPL 开源，C# 编写，有成熟的列车物理模型，但面向游戏模拟，封装为 RL 环境工程量大，仅作参考。

- **OpenBVE / Libre-TrainSim**：开源但本质是驾驶游戏，不适合 RL 集成
- **Train Sim World / Trainz / Run8**：商业闭源游戏，无法修改模拟核心
- **OpenTrack**（ETH Zurich）：有基本的列车质点运动动力学（牵引力→加速度→速度→位置，通过数值积分计算），但其核心用途是时刻表规划与线路运营能力分析，**不涉及多车厢间的纵向耦合动力学**（车钩力、松弛行为等）。需商业许可。
- **RailSys**（RMCon）：商业列车运行仿真软件，用于信号系统设计和运行时分分析，同样**不涉及详细的车钩力等纵向动力学建模**。需商业许可。

### 7.5 学术调研：列车动力学仿真方法

为了全面了解学术界如何进行列车动力学仿真，对近年来的相关论文进行了系统性检索和整理。

#### 7.5.1 动力学建模流派

学术界对列车动力学的建模可分为三个层次：

**流派一：单质点模型（Single Mass Point Model）**

将整列列车视为一个质点，运动方程为：
$$M \frac{dv}{dt} = F_t - F_b - R_b(v) - R_g(x) - R_c(x)$$

- **适用场景**：宏观运行优化（时刻表、节能调度）
- **使用团队**：绝大多数列车运行优化/调度论文使用此模型
- **缺点**：忽略车钩力，无法模拟车厢间的拉扯/挤压
- **代表论文**：
  - Rong et al. (2025, BJTU) — 虚拟编队抗干扰控制，使用 H∞ 控制器设计
  - Lu et al. (2025, 西南交大) — 重载列车速度轨迹协同优化，使用 MILP/CPLEX

**流派二：多质点模型（Multi-Particle / LTD）← 推荐用于 RL 环境**

每节车视为一个质点，通过车钩弹簧-阻尼连接：
$$m_i\ddot{x}_i = F_{t,i} - F_{b,i} - R_i(v_i) - R_{g,i}(x_i) + F_{c,i-1} - F_{c,i+1}$$

- **使用团队**：大连交通大学魏伟团队（国内列车纵向动力学最活跃的课题组）、中央昆士兰大学 CRE 团队（Cole/Wu/Spiryagin）
- **优点**：能准确模拟车钩力、纵向冲动、空气制动波传播
- **代表论文**：

| 论文 | 团队 | 核心方法 |
|:---|:---|:---|
| 朱绩超等 (2025), *工程力学* | 大连交通大学 | 多刚体 + 空气流动理论，PDF可下载 |
| Wang et al. (2025), *World J. Eng. Technol.* | 朔黄铁路 | 30,000吨重载列车多质点模型，PDF可下载 |
| Aredah et al. (2024), *Railway Engineering Science* | Virginia Tech (NeTrainSim) | 网络级纵向动力学仿真，开放获取 |

**流派三：多体动力学模型（Multibody Dynamics）**

每节车作为多刚体系统（车体6DOF+转向架6DOF×2+轮对5DOF×4），使用商业 MBD 软件。

- **典型工具**：Simpack（Dassault）、Adams/Rail（MSC）、GENSYS
- **适用场景**：轮轨磨耗、脱轨安全性、车辆-轨道耦合振动
- **不适用 RL 的原因**：自由度极高，单步仿真耗时秒级，RL 需要百万级步数

#### 7.5.2 RL + 列车控制的最新研究

**发现 1：MAPPO 已应用于重载列车群组协同控制**

**Song, Li, Wang & Yang (2026)** — *Cooperative Control for Heavy-Haul Train Groups Based on Multi-Agent Reinforcement Learning*

- **链接**：[中国科技论文在线](https://paper.edu.cn/releasepaper/content/202605-114)（摘要可见，全文暂未公开）
- **核心设计**：
  - 建立详细的重载列车纵向动力学模型作为仿真环境
  - **算法：MAPPO**（多智能体 PPO），CTDE 架构
  - 每列车 = 一个 agent，学习速度同步和间距保持
  - 奖励函数：势场安全引导 + 多目标优化
  - 结果：速度同步精度显著提升，总牵引能耗降低，零安全违规
- **启示**：验证了 MAPPO 用于列车编队的可行性，与本项目方向一致

**发现 2：虚拟编组（Virtual Coupling）是热门方向**

虚拟编组本质上就是列车版的"编队控制/platooning"，与无人机编队问题高度同构：

| Zhou et al. (BJTU) | 基于 TD3 的速度轨迹优化 | 旅客列车 |
| Rong et al. (BJTU, 2025) | 博弈论 + H∞ 抗干扰控制 | 重载列车虚拟编队 |
