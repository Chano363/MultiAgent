# 安全层与车钩保护（V13）

**状态**：已闭合（**假设被证伪，但查出了更严重的问题**）｜ **级别**：C（代码）+ C（实测）

> 本条起初被判为"配置写错"（`release` 只适用单列，却用于 3 列编队）。**该判断错误。** 真正的缺陷在规则 A 的**作用对象**，与 `release/min_brake` 无关。以下保留完整过程，因为"为什么原判断错了"本身有诊断价值。

## 1. 原假设

峰值时刻三条列的电制动实际深度为 `[1.00, 0.00, 1.00]`（中间列无电制动）。原解释：安全层规则 A 的 `release` 模式在车钩力触 1 000 kN 时把 ED 钳零 → 失速 → 峰值反升。若成立，改成 `min_brake`（保留 30% 制动）应当降峰。

## 2. 实验（同 ckpt、只改 YAML）

- ckpt：`mappo_fleet_ep61_dec_ad2_cp_seed0.pt`（与阶段 1 同一个）
- 唯一变化：`_probe_loco_notch_v2_20ep.yaml:68`、`formation_ed_ab_3train_1plus108.yaml:106` 的 `coupler_override: release → min_brake`
- 命令、剖面、seed、步数全部与阶段 1 一致（31500 步 / `--eval_seed 0` / `n_seed 1`）
- 结果文件：`outputs/results/decompose/eval_decompose_decompose_m1_ms31500_v13_minbrake.json`
- 耗时 15 min 51 s，exit 0

## 3. 根因（单元测试，决定性）

对安全层做最小单元测试：109 辆车、机车在 index 0（`action=-0.77` 表示 ED 77%）、车钩力在 index 5 处 1300 kN。

| 模式 | 机车动作 in → out | 超限车 index 5 的 out | 事件 |
|---|---|---|---|
| `release` | **−0.770 → −0.770** | +0.000 | `coupler_force_limit` |
| `min_brake` | **−0.770 → −0.770** | +0.000 | `coupler_force_limit` |

**规则 A 是逐车作用的**（`safety_layer.py:270`）：

```python
for i in range(self.num_vehicles):
    if coupler_forces[i] >= coupler_limit:
        ...
        actions[i] = 0.0            # release
        # 或 actions[i] = max(actions[i], MIN_BRAKE)   # min_brake
```

它只改**超限那一辆车自己**的动作。而 1+0 编组里：

- 动作只存在于**机车**（1 辆车，index 0）
- 车钩力超限发生在**货车**（index 5 这类），而货车动作恒为 0
- ⇒ `release` 把 0 变 0，`min_brake` 把 `max(0, −0.3) = 0` 变 0

**两种模式在 1+0 编组下完全等价，且都等于"什么也没做"。** 机车那份真正的制动力从来没有被削减过。

这也解释了为什么 `safety_events` 高达 119 306 次却毫无效果——事件在记，动作是空转。

## 4. 判决

| 项 | 结论 |
|---|---|
| 原假设（release 钳零 ED 致峰） | **证伪** |
| `release` vs `min_brake` | **无关紧要**，1+0 编组下等价且都无效 |
| 真正缺陷 | **规则 A 的作用对象错了**：它假设每辆车都有可削减的动作，这在分布式动力编组成立，在 1+0 单机车编组不成立 |
| 影响面 | 车钩力保护层在 1+0 编组下**等于不存在**。十轮训练 `peak_coupler` 从未 <1000（ADR-065 背景第 1 条），与"保护层实际失效"直接吻合 |
| 对阶段 1 的影响 | **无**。1271.1 这个数不受影响（两种模式都无效，阶段 1 跑的就是实际情况）。此前的 V09/V10/V14 归因**须再更正**：ED 归零与 AB 脉冲不是规则 A 造成的 |

## 5. 附带更正：ED 归零与 AB 脉冲的真正来源

V13 原判"规则 A 释放 ED 与 AB"，现被证伪。`telemetry.npz` 里 `ed_actual=0`、AB 只有 0.1 s 的现象**另有原因**，目前未定，候选：

1. `train_env.py:668` 的 `if ed_frac < 0:` 分支——负动作被判为**牵引**，`ed_throttle=0`。但 `get_action_notch` 的输出下限是 0.27，理论上不会为负；**除非 telemetry 记的是 RL 原始动作（−0.023）而非映射后的 ED**。
2. `ed_throttle = min(ed_throttle, protected_depth)` 在非 ATP 情形下的 `protected_depth` 取值。
3. AB 的 0.1 s 脉冲来自 `_ab_gate` 充风门控（222 s）与 `AB_NOTCH_LEVELS` 量化的交互，而非规则 A。

⇒ **这三项须另立条目查证**（见 `LEDGER` V15，待查），在查清前，`50_编队协同.md` 中"规则 A 一并释放 AB"的表述**已标为不成立**。

## 6. 修复方向（需设计，不是改配置）

规则 A 要真正生效，必须把"某处车钩超限"映射到"削减**可执行动作**的车辆"：

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A** | 超限时削减**全部机车**的制动力（按超限幅度阶梯下调） | 改 `safety_layer.py` 一处 | 长下坡失去制动力可能失速——须同时给 ED 下限保护 |
| B | 只削减**最近的机车**（按位置距离） | 同上，需位置索引 | 1+0 时退化为 A |
| C | 放弃逐车，改为**列级聚合**：任一车钩超限 → 该列机车动作按比例降 | 改动较大，但语义最正确 | 需重新定义"按比例" |

**共同前提**：任何"削减制动"都可能在 −11‰ 上造成失速，必须与"ED 下限/失速保护"成对设计，否则会重现 `safety_layer.py:255` 记录的自毁闭环。

**执行建议**：属阶段 3（改安全层 = 改机制），不在阶段 1/2 允许范围内；且改完必须重训，须与限速改动分开验证。

## 7. 教训

1. **"配置与注释冲突"不等于"配置导致了观察到的现象"。** 我依据注释判定 `release` 是元凶，实测证明它连"凶手"的资格都没有——规则从未作用于机车。
2. **单元测试比整套评估便宜 1000 倍。** 15 分钟的评估只证明了"无差别"，10 秒的单元测试直接给出了"为什么"。
3. **`safety_events` 计数不能当作"保护生效"的证据。** 11.9 万次事件、零动作改变。任何"安全层在起作用"的论断都应附带"动作是否真的被改写"的检查。
