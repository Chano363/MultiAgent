## 一、需要拍板的事项（只有一件）

**第 11 投（下一轮正式训练窗口）要不要开？开的话按哪套判据？**

**2026-11-21 更新（诊断 §19.47）**：owner 指出"车钩力压下来之后一直在做列距"——本项目主 claim（ADR-042 / `RESEARCH_POSITIONING.md` §1.6）就是**编队指标收益**（列距保持 + 列间速度差收敛），车钩峰值只是**工程口径底线**、不作对比胜出主张。§19.47 按主指标重做了"训练期量 → 评估态"相关性，**靶子因此改变**（详见 §四）：

| 项 | 更新后的定位 |
| :--- | :--- |
| **止损信号** | 训练期奖励分量 **`speed_band_sum`**（速度带惩罚）——**主指标口径下唯一留一法稳定同向**的量（~评估态 gapMean **+0.821** / gapPeak **+0.857** / band **+0.670**），**已在既有落盘 `train_reward_terms_*.csv` 里，不需要新通道** |
| **不能用** | 训练期**代价型**标量（peak / viol / overspeed / `gap_err_mean` / `gap_min_m`）——它们与评估态**主指标方向相反**（`gap_err_mean` ~ gapMean = **−0.571**、`gap_min_m` ~ gapMin = **−0.723**，均留一法稳定反号）⇒ 在主指标口径上**在线止损同样不可行**（此前只在峰值口径上被否） |
| **目标表述** | "**主指标（列距 / 速度带）不随集数退化**"，**不是**"车钩峰值别破线"——后者是工程口径，且 ep6 的峰值破线在主指标上几乎不伴随退化（ep6 gapMean 725.8 排第 4、gapPeak 1301.5 排第 3、band 0.9067 正常、零穿透；真正最差的是 ep1） |
| **逐列通道的定位** | §19.45 的逐列车钩力量落盘**不是止损所必需**（`speed_band_sum` 已在既有落盘），它保留为**诊断通道**（判断哪一列/哪种形态在漂移）；**不再作为候选成立的前置条件** |
| **⚠️ 该靶子的浮点噪声限定**（§19.48） | 同机同码下**仅 1 ULP 的策略输入扰动**，整程车钩峰值即漂移 **−14.9%**、超限漂移 **−33.9%** ⇒ **凡"改善 N%"的说法，N 与该量级同阶时只能降级为"有可区分差异"**；且 §19.47 的主指标相关性读数**本身尚未做浮点噪声核验**（探针在跑）⇒ **本靶子当前处于"待噪声核验"状态**，引用时须带限定 |
| **⚠️ 跨机可搬运性限定**（§19.49） | 主指标口径**内部稳健性极不均匀**：`band_rate` 跨机仅差 **0.15%**、`gap_min_m` **0.02%**，但 `gap_err_mean_abs_m` 可差 **53.5%**、`gap_err_peak_abs_m` 28.1% ⇒ **§19.47 的三个相关性中只有 `~band_rate`（+0.670）建立在跨机鲁棒的量上**，`~gapErrMean`（+0.821）/ `~gapErrPeak`（+0.857）建立在最不稳的两个量上 ⇒ **它们不构成"三次验证"，而是"一次稳健 + 两次脆弱"** |
| **⚠️ 新增的零成本前置动作**（§19.49） | 第 11 投窗口在**云端**开，而 §19.47 的标定在**本地**做 ⇒ **本地标定只能当先验、不能当判据** ⇒ **开窗后须先在云端机重跑 ep1–ep7 官方快评标定**（分析器可复用、只换产物输入），**再**在云端窗口上验证信号。另：**`gap_err_mean_abs_m` 的集间最好/最差在跨机下完全翻转** ⇒ **ckpt 选择必须在同一台机器上完成** |
| **该窗口的首要产出** | **`speed_band_sum` 信号能否跨 seed、跨集数成立**——目前只在 n=7、且最差集 ep1 属训练早期未收敛集（reward −72230）上验证过 ⇒ 这是必须用新窗口回答的问题 |

**建议**：开一次 20 集窗口（≈2.4 元），带既有 `train_reward_terms` 落盘 + §19.45 逐列通道 + 云端环境指纹（规则第 9 条）。该窗口同时回答三件事：① `speed_band_sum` 信号跨 seed 是否成立；② 主指标是否随集数退化；③ 云端 ISA/指纹实测（闭合跨机读数纪律）。

## 二、已确证的事实（可放心引用）

1. **跨机器 17.7% 差异来自机器而非代码**（§19.42）：本地两次跑逐位一致（peak 1478.85），云端 1256.72。
2. **代码同源已由推断升级为实证**（§19.43）：`.preflight_ok` 记 `commit=1bb7b02` + 祖先核验 + `src/` 路径 diff 三重旁证 ⇒ 云端跑的就是本地这版数值代码；顺带定位 `metadata.git_commit` 失真的**具体成因**（云端 `.git` 部署残留 + `rev-parse` 成功但返回过期值）。
3. **两个浮点候选层已被实测排除**（§19.43）：线程序/BLAS 线程归约顺序（6 档线程 md5 唯一）、numba JIT 目标 ISA（5 目标 md5 唯一）⇒ **不得再怀疑这两项**。
4. **逐列车钩力量在评估态确有信号**（§19.44）：`col1_peak_kN` / `col1_viol_steps` / `spread_col_peak_kN` 能把破线集 ep6 排第 1、ep7 排第 3–4、**误杀集为空**；但全局总 peak 同样满足全部要求 ⇒ **评估态侧逐列分解相对总 peak 无可用增量**。
5. **头列/尾列逐列量无区分力**（§19.44）：ep6 排第 7/第 6（比 ep7 还差）⇒ 逐列判据须绑中列或**列间离散度**；而"哪一列承压"**跨机器会翻转**（§19.42）⇒ **列身份不是可跨机器固化的靶子**。
6. **训练期逐列落盘通道已就位**（§19.45）：纯新增观测、零物理改动、零额外仿真成本；守卫 12 项（含动态只读性检验：多读一次断面力后轨迹逐位相同）+ 端到端冒烟贯通。
7. **跨机 17.7% 差异在机制层已收口**（§19.48）：放大探针整程实测——0 ULP ⇒ peak **1478.8515764313 kN**（与 ep6 基线**逐位一致**，零回归自证）；**1 ULP ⇒ 1258.9060186688 kN（−14.9%）、viol 3400（−33.9%）** ⇒ **1 ULP 级微差足以解释跨机 17.7% 差异** ⇒ 无需再定位到具体哪一位。**⚠️ 这不等于"已定位根因"**（根因需两机指纹逐项比对），但**幅度层的可解释性已闭合**。
8. **跨机主指标漂移带已实测**（§19.49，零新增机时）：`band_rate` ±0.15% / `gap_min_m` ±0.02% / `gap_err_mean_abs_m` ±53.5% / `viol` ±70.2% / `peak_coupler_kN` ±15.0%；且 `gap_err_mean_abs_m` 的**集间最好/最差在跨机下完全翻转**。
9. **训练期同向性判据执行器已就位**（§19.45 补记）：`analyze_train_col_collinearity.py`（Spearman + 单阈值可分性 + ep3 误杀硬约束），窗口数据到位后一条命令出判决。

## 三、已否证 / 已排除（不要再提）

- **用训练期标量止损**（§19.41）：破线代价型四指标与评估态 peak 的秩相关**全为负**（peak −0.679 / coupler_over −0.536 / violations −0.464 / overspeed −0.393）⇒ **方向是反的**；唯一同向的 `gap_eff` 存在**排序矛盾**（ep7 的 gap_eff 高于 ep6，而 ep7 评估 peak 低于 ep6）⇒ **任何单阈值都分不开 ep6 与 ep7**。
- **逐列 AB 派生阈值作为训练期机制**（ADR-082）：跨 ckpt 泛化失败、收益反号 ⇒ 是 ep6 的事后诊断/回退手段，**不是可从 ep1 引入的训练期机制**。
- **numpy 版本差异**（2026-09 小节-三）：本地 2.2.5↔2.2.6 切换后偏差 0.0000%（⚠️ 该对照在 BC 归档场景，非本项目 fleet 场景）。
- **线程序、numba JIT 目标 ISA**（§19.43）。
- **⚠️ 幅度类相对结论**（§19.48 新增）：**"X 比 Y 好 N%"** 这类表述，在 N 与浮点噪声带（1 ULP ⇒ −14.9%）同阶时**一律不得再主张**（受影响：§19.34 的 `bias_n` "−21.7%"、§19.33 的 ep4→ep6 "+11.0% ⇒ BREAK"）。**机制存在性结论不受影响**（AB 分配、逐列均衡、追尾为零等结构事实与浮点噪声无关）。

## 四、未闭合项（本简报不掩盖）

1. **训练期逐列量与评估态是否同向**（候选前提②的唯一剩余未知项）⇒ 需一次带落盘的重训窗口。
2. **跨机器差异的具体放大层**（§19.43/§19.46）：剩余候选 = 库版本 / BLAS 实现 / libm / 归约次序；**候选已收窄为一条具体事实**：本地 torch 是 cu121 wheel（MKL-DNN v3.5.3 / oneAPI MKL 2024.2 / AVX2），云端镜像记载为 CPU 版 torch 2.5.1 ⇒ **同版本不同构建 ⇒ GEMM 归约路径可能不同**；探针 C（策略前向 ISA 路径）与云端指纹采集**结果待补**。
3. **浮点漂移带（部分闭合）**（§19.48）：**峰值口径已测出 1 ULP ⇒ −14.9%**（跨机 17.7% 差异因此在机制层收口）；**10/100 ULP 档待补** ⇒ **不得据单一非零扰动点拟合放大系数函数或外推**；**⚠️ 主指标口径（列距/速度带）的漂移带尚未实测**（探针 `probe_primary_metric_sensitivity.py` 已建，计划任务 `MultiAgent_ADR083_primarysens` 排队中）⇒ **§19.47 的主指标相关性结论当前处于"待噪声核验"状态**（判读规则已前置写死：主指标漂移 ≫ 信号幅度 ⇒ §19.47 结论不可用、须另找抗噪信号；≪ ⇒ 不受威胁、可继续作靶子）。
4. **W4 closer 第二次未兜住收账**（§19.33）：closer 被终止（Result=0x800703E3、Missed=3），早于破线 14 分钟 ⇒ 收账与停机由 agent 手动完成（空转约 4.8 min）⇒ 修复版护栏（5 min 触发器 + billing_guard）的**端到端复测**仍待开窗。
5. **⚠️ §19.47 靶子的噪声前提未闭合**：见上第 3 条——`speed_band_sum` 与主指标的相关性（+0.821/+0.857/+0.670）**尚未证明不是浮点噪声**。⇒ 这条**先于**跨 seed 验证：若主指标漂移带与该信号同阶，则换 seed 也只是量噪声。
6. **⚠️ 云端标定未做**（§19.49）：§19.47 的相关性/阈值全部来自**本地**口径 ⇒ 搬到云端前**必须先在云端重标定**（零额外机时，但需开窗后占用评估时间）。
7. **`speed_band_sum` 信号的稳健性未知**（§19.47）：n=7、最差集 ep1 属训练早期未收敛集 ⇒ 它可能只是"抓到了没收敛"，**未必**抓得住"训练中后期漂移"；跨 seed / 跨集数验证是新窗口的首要任务。

## 六、风险提示

- **止损候选可能仍不成立**：§19.47 已把信号缩到唯一一个（`speed_band_sum`），但它只在 n=7 上验证过 ⇒ 窗口跑完若跨 seed 不成立（Spearman 变号 / 单阈值分不开），**该路线就地关闭**，不再加机制。
- **止损的收益形态**：它的作用是"**不让训练漂到主指标退化的形态**"，而不是"提升峰值上限" ⇒ 定位是**稳定性/一致性**，不是性能提升。
