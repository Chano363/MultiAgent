# 模板：记录失败 / 踩坑（进 `.learnings/LEARNINGS.md`）

> **追加规则**：append-only，新格在文件末尾。越挫越勇的缓解，格式越统一越有用——
> 审稿/复现/交接都靠它。复制模板替换 `[...]`。

---

### [日期] 标题（一句话现象）

- **现象**：复现路径 —— 在什么命令/操作下出现什么错误/异常
- **期望 vs 实际**
  - 期望：X
  - 实际：Y（贴关键报错/log 片段）
- **根因（三层追）**
  1. 表象：直接报错
  2. 机制：代码/物理/逻辑上的真正原因
  3. 为什么没早发现：缺哪道检查/哪个环节本该拦住
- **解决**：改了哪个文件哪一行；**证明已修好**：复跑哪些测试/实验通过（如 `pytest -q` 数字、关键指标）
- **止血与预防（复用价值所在）**
  - 本次怎么绕开
  - 长期如何不再犯（与其对应的 `CHECKLIST`/AGENTS Gotcha 条目）
- **类型标签**：`物理建模` / `训练数值` / `算法逻辑` / `工具链` / `参数配置` / `环境依赖`

---

### 反例
- ❌ 只记"解决了"，删掉或省略踩坑过程 → 违反工作留痕规范
- ❌ 不写根因的"为什么没早发现" → 预防无从下手
- ❌ 与某处诊断重复且不复用 → 用链接指向真身，不复制
