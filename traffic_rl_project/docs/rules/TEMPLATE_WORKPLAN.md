# 模板：追加工作计划（进 `docs/PROJECT_PIPELINE.md`）

> **追加规则**：本模板是**追加到文件末尾的独立小节**；已完成的条目 ✅ 保留不删，
> 新任务一律在文件尾部新开小节。复制下面模板，替换 `[...]` 后粘贴。

---

### [P?] 任务标题 - 实施日期

- **状态**：🆕 新增 ／ 🔄 进行中 ／ ✅ 完成 ／ ⛔ 放弃 ／ ⏸ 挂起
- **归属**：P0/P1/P2/P3 · 对应论文小节（如 Methods / Experiments）
- **动机/背景**：为什么做（可追溯到 老师意见 / 论文缺口 / 诊断发现 / 工程故障）
- **完成判据（验收）**：一句话；必须有可量化指标。示例：
  - ✅ = 车钩力峰值 ≤ 1000kN 且 0 追尾，M1 相对 M3 协同增量 ≥ +X
  - ❌ = 期望 X，实际 Y，原因：...
- **方法/关键命令**：`python src/trainer/xxx.py --episodes N --seed S --checkpoint_dir ...`（完整可复现）
- **配置**：seed / 关键超参（YAML 片段或 config），确保可追溯
- **结果（完成后补）**
  - ✅ 成功：复现证据（数据表 + 图 computer:// 链接 + 日志）
  - ❌ 失败：失败原因、期望 vs 实际、如何解决 ——**失败的痕迹同等重要，不删**
- **产出文件**：
  - 结果/图表/日志：`computer://d:\Code\MultiAgent\traffic_rl_project\outputs\...`
  - 数据记录：`docs/logs/diagnostics/DIAGNOSTICS_YYYY-MM.md` 中「### 诊断-日期-主题」

---

### 反例（不要这样做）
- ❌ 覆盖或改写历史条目 → 论文溯源丢失
- ❌ 只写"完成了"不给复现命令/配置 → 数据无法复现
- ❌ 给同一个任务开两个位置 → 破坏 SSOT，改一处乱两处
