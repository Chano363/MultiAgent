# 文档规范总览（Docs-as-Code 最佳实践落地）

本目录是本项目**唯一**的文档治理层。所有文档协作依据这里，所有新文档必须先读
`CHECKLIST_NEW_DOC.md`。

---

## 一、本项目文档架构（角色分层）

每类文档有明确职责、Owner、生命周期（SSOT 详见纪律 1）。

| 目录/文档 | 角色 | 生命周期 | 谁追加 |
|---|---|---|---|
| `README.md`（仓库根） | **项目护照**：定位 / 快速开始 / 一级目录 / 文档入口（详见 §六） | 覆盖式修订，硬上限 100 行 | Owner |
| `AGENTS.md`（仓库根） | **操作契约**：环境 / 硬红线 / 开工前必读 / 真源优先级 / 校验边界（详见 §六） | 覆盖式修订，硬上限 80 行 | Owner |
| `docs/rules/` | 规范 + 模板（本文档体系就是它） | 修订走 review，只更新不覆盖历史规则记录 | 项目 Owner |
| `docs/README.md` | **导航地图**：所有文档入口，唯一索引 | 增删文档时同步 | 项目 Owner |
| `docs/PROJECT_PIPELINE.md` | **仅 §〇 是现行状态**（在跑/序/挂起/工程债）；§一 §二 为历史与流水的索引，不放正文 | §〇 覆盖式修订；历史按月迁 `logs/progress/` | Owner + Agent |

## 二、八条最佳实践纪律（大厂对齐）

1. **单一事实源 SSOT**：不重复；要引用用链接。数据只在产生它的文档记录，其他页面链接。
2. **职责分离**：验证 / 诊断 / 决策 / 踩坑 / 日志 / 论文 各归其位，不混装。
3. **Front Matter**：每个文档顶部 YAML 块 `title / date / status / owner / supersedes`。
4. **变更走 review**：重要文档随代码进 git；决策记录只追加，废弃用 `supersedes`，不篡改旧文。
5. **少即多**：单文件超阈值(约 200KB)必须拆分或新建承接文件；旧内容保留，新内容进新文件。
6. **append-only 留痕**：工作/诊断/决策都只追加小节，历史命令/结论是论文溯源基础，绝不覆盖。
7. **导航登记**：新建文档必须登记进 `docs/README.md`，否则等于没建。
8. **临时物即生即清**：临时脚本用后即删或移 `outputs/`，不留在根目录。

## 三、三类核心模板（追加/总结/记录）

| 场景 | 用哪个模板 |
|---|---|
| 新增/修改计划（写进 `PROJECT_PIPELINE.md` §〇 0.1/0.2/0.3/0.6） | `TEMPLATE_WORKPLAN.md` |
| 已完结的执行条目按月归档到 `logs/progress/` | `TEMPLATE_WORKPLAN.md`（整条原样迁出，标题不变） |
| 记录一次失败/踩坑到 `docs/logs/learnings/LEARNINGS.md` | `TEMPLATE_FAILURE.md` |
| 沉淀一条可复用历史经验（区别于一次性教训） | `TEMPLATE_EXPERIENCE.md` |
| 新建任何文档前 | `CHECKLIST_NEW_DOC.md`（必读） |

## 四、快速判断"这条我要写进哪个文件"

```
我要记录的是？
├─ 一个实验/诊断跑出的数据 + 复现命令          → logs/diagnostics/DIAGNOSTICS_YYYY-MM.md（按月，append）
├─ 我做了个重要技术/方向决策                     → logs/decisions/DECISIONS.md
├─ 我踩坑了、修了、怎么避免复发                  → logs/learnings/LEARNINGS.md
├─ 我新增一个要做的任务/计划                      → PROJECT_PIPELINE.md **§〇 现行状态**（先判断落在 0.1/0.2/0.3 哪一格）
├─ 一条历史任务的执行记录/结果（PIPELINE 已过长）    → 按月追加到 logs/progress/PROGRESS_YYYY-MM.md（append-only）
├─ 今天的工作流水（做了什么/卡在哪）              → .codebuddy/memory/YYYY-MM-DD.md（每日日志）
├─ 一条能复用的方法论/知识（有出处、有反例）       → TEMPLATE_EXPERIENCE 沉淀
├─ 从文献核实/讨论出的证据、术语口径、同类工作对照   → docs/papers/LITERATURE_FINDINGS.md（立论文档只留结论指针）
├─ 我在改仓库根的 README / AGENTS（加段落前先问该不该加） → 本文件 §六 职责边界 + 三条判据
└─ 论文/对外交付物                                → 暂无（原 ITSC_PAPER.* 已删除，重写时新建）
```

## 五、计划状态规范（2026-11-12 新增；针对"计划到处都是"）

> **病根**：纪律 1/6（SSOT + append-only）只管住了"数据不重复"和"历史不覆盖"，**没管住"哪条还有效"**。
> 结果：PIPELINE 里并存 5 个 2026-08 的「当前执行」小节、98 条 2026-10 流水，唯一的现行任务埋在倒数 30 行；
> 计划另散在 ADR 的「后果/待办」、README 导航、STATUS 周报、`HANDOFF_*`、`.trae/documents/*.md` 五处。
> 以下六条为硬规范，新增/修改计划时逐条自查。

1. **唯一「现在」层（R1）**：全仓只有 `PROJECT_PIPELINE.md` §〇 可以写"现在做什么"。其他任何文档描述现状，**只能引用 §〇，不得自述**（周报/汇报可以摘抄，但必须标"摘自 §〇，以 §〇 为准"）。
2. **禁止无日期形容词（R2）**："当前执行 / 正在跑 / 下一步"必须带确认日期，且生命周期 ≤ 一次任务闭环。**闭环当天**改为 ✅/❌ 并移出 §〇，不许留在正文里继续冒充现状。
3. **挂起必须写触发条件（R3）**：进 §〇 0.3 的挂起项必须写"什么事件/判据一出现就重启"，且该条件可判定。"以后可能做 / 有需要再说"**不是挂起，直接不写**——写了就是负债。
4. **原位陈旧横幅（R4）**：被取代的小节**不删原文**，在标题下第一行加 `> ⛔ 已被 ADR-0XX 取代（YYYY-MM-DD），不再执行，原文保留仅存档`。判断是否过期，看横幅而不是看标题里的日期。
5. **ADR 待办双登记（R5）**：ADR 正文写决策与原委；其中**未闭环的待办**必须在 §〇 0.4 有一行（ADR 编号 + 一句话 + 状态）。闭环时回 ADR 追加"已执行"，并更新 0.4。**只在 ADR 里写待办 = 必漏**（实例：ADR-064 待办③ 挂了 1 天没执行，直接把"1400 集"漏进了对外结论）。
6. **数字必须带口径三要素（R6）**：引用训练量只能写 `集数 × 每集步数 = 总 env-steps（+ 更新次数）`，禁止单抄集数；引用成本必须同时给"单价来源 + 是否已批复"。**未批复的参考值一律标 ⛔**（实例：`SERVER_OPS.md` 的 358 h/515 元/89 h/600 元 已作废）。

**自查三问（每次动计划前）**：① 这条写的是"现在"还是"历史"？现在→§〇，历史→流水。② 它跟 §〇 有冲突吗？有→先改 §〇，别在别处补一句。③ 它的数字能不能追到一条带日期的决策？追不到→不许写。

## 六、README.md / AGENTS.md 职责边界（2026-11-12 立）

> **病根**：§一 给 `PROJECT_PIPELINE` / `RESEARCH_POSITIONING` / `logs/*` 都定义了角色，唯独没定义仓库里被读得最多的两个文件。结果：**没被定义职责的文件一定膨胀成垃圾桶**——`AGENTS.md` 长到 222 行 / 26.8 KB，约 130 行是别处已有内容的转述；`README.md` 反向退化，停在无人机时期，连启动命令都是错的。

**一句话**：`README.md` 是**项目护照**（给人看：这是什么、怎么跑）；`AGENTS.md` 是**操作契约**（给零记忆的执行者看：不许做什么、先读什么）。两者都是**派生视图，不是真源**——它们唯一有权独占的"事实"只有一类：**导航元数据**（谁在哪、先读谁、冲突听谁的）。

| | `README.md` | `AGENTS.md` |
| :--- | :--- | :--- |
| 读者 | 第一次打开仓库的人（新人 / 导师 / 审稿人 / 半年后的自己） | 无上下文、无记忆的执行者（AI agent 及其操作人） |
| 回答的问题 | 这是什么？凭什么值得跑？怎么跑起来？东西在哪？ | 绝对不能做什么？动手前必读什么？冲突时听谁的？ |
| **必须写** | ① 一句话定位 + 研究对象与范围　② 现行状态**指针**（→ PIPELINE §〇，不自述）　③ 最小可运行命令（可复制粘贴即通）　④ 一级目录地图（≤15 行）　⑤ 文档入口 3–5 条　⑥ 首次跑不通的常见原因（缺数据 / 缺环境） | ① 环境与入口（≤8 行）　② 硬红线（违反即出事，每条 ≤2 行 + 指针）　③ 开工前必读表（改 X → 读 Y → 不读的后果）　④ 真源优先级　⑤ 校验能力边界（机器校验管不到什么） |
| **禁止写** | 规则条文、ADR 编号连缀、进度表、日期快照、历史阶段细节、**未达成的指标值**（写成目标可以，写成现状不行） | 立论论证、研究定位细节、规则完整条文、命令清单（README 已有）、任何"现在在做什么" |
| 长度上限 | 100 行 | 80 行 |

**权威等级（冲突时按此顺序，不是"看哪份"）**：
`DECISIONS.md` / `RESEARCH_POSITIONING.md`（立论）> `docs/rules/*`（执行规范）> `PROJECT_PIPELINE.md` §〇（计划）> `README.md` / `AGENTS.md`（导航）。
**推论**：两个入口文件**无权对任何事实作终局解释**。README 与 AGENTS 打架 = **两份都错**，回正本改。

### 三条判据（写完自查，任一条不过就删）

1. **正本测试**：正本改了，这一行**是否必须跟着改**？否 ⇒ 它是抄件，删成指针。
2. **删除测试**：删掉这段，会不会有人**因此做错事**（跑错命令 / 改错文件 / 花错钱 / 写出被审稿人打回的句子）？否 ⇒ 删。
3. **编号密度测试**：一段里出现 ≥3 个 ADR 编号 ⇒ 它是立论文本，搬 `RESEARCH_POSITIONING.md`，此处只留一句结论 + 指针。

### 三条溢出规则

1. **想写的东西无处可去 ⇒ 说明 `rules/` 缺一章**，去补 `rules/`，别把 AGENTS 当规范的家。
2. **红线可摘要，正文不搬**：金钱 / 数据安全级（开云实例、删产物、改物理）允许在 AGENTS 留 ≤3 行摘要 + 指针；其余规则一律只给指针。
3. **同一条信息只许一处全文**：README 与 AGENTS 若重复，按"谁离读者近"保留一处，另一处改为一句话链接。
