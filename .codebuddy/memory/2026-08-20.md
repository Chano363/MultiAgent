## 核心定位澄清（2026-08-20，用户纠正，务必记住）

**用户明确（纠正我的错误理解）**：
> "车钩力本来就是列内处理的，编队是为了维持各个列车之间的距离需要循环制动，导致列内车钩力发生变化。这是我论文的核心。这不和物理冲突，所以是你搞错了。"

**正确逻辑链（项目核心定位）**：
1. **车钩力在列内处理**（每列内部车厢间机械钩缓，制动-缓解产生）——不冲突
2. **编队的价值** = 维持各列车之间的**距离**，而维持距离需要**循环制动**（长大下坡必须制动控速）
3. **编队→循环制动→列内车钩力变化**：一列为配合编队距离而制动/缓解 → 该列**列内**车钩力变化
4. **核心创新点** = 多列编队协同（为保持间距的循环制动节奏配合）**影响/约束每列内部车钩力**

**"错开"为何相关**：各列为保持间距，循环制动相位/节奏不同（前列先制动、后列配合）→ 某列因配合间距而急制动/缓解 → 列内车钩力放大。**协同价值 = 保持间距的同时，控制/最小化每列车钩力**（避免为追尾而急制动导致列内车钩力爆表）。

**正确对比**：
- **M1（群组协同）**：协调各列制动/缓解节奏保持间距 + 控制每列车钩力
- **M3（单列独立）**：每列只按自己速度循环制动，不管间距 → 追尾需急制动 → 列内车钩力大/牺牲速度

**与 Zhang2024 区别**：Zhang2024 单列循环制动，无"为保持编队距离"的约束；**我们的创新 = 在"多列必须保持间距"约束下协同循环制动，同时守住每列的车钩力**。

**我之前错误**：把车钩力当成"多列之间"的机械耦合 → 困惑"多列无机械钩挂"。实际是"多列协同→影响每列循环制动节奏→影响该列内部车钩力"。

## 用户纠错：APF 势场解耦架构是生搬硬套（2026-08-20）

**用户明确指出**：Zhang2021/Guo2025 的 **APF 势场控制器"解耦"是从地铁/汽车平直场景生搬硬套**，属于文档里的错误内容，不得作为本项目的重构依据。

**为什么 APF 对本场景是错的（已确认）**：
- Zhang2021 = 地铁**平直**线路、**单质点、忽略车钩力、无坡度** → 与朔黄线长大下坡 + 多体车钩力 + 循环制动物理完全不符
- APF `tanh(间距误差)+tanh(速度差)` 假设车辆可自由±加减速；而长大下坡列车**无法牵引超速、只能制动降速**（向下可制动、向上无牵引），±对称的 APF 修正与循环制动离散档位节奏天然冲突
- Guo2025 = 汽车编队（CACC），同样无车钩力/坡度/循环制动概念
- **结论：不能采用"RL 出宏观意图 → 确定性 APF 势场转 throttle"这条解耦路径**

**正确的分层（仅魏咪车钩力分层框架可借鉴，且不是 APF）**：
